# 纯 Python 虚拟工作台运行说明

版本：`v1`
适用范围：当前无实机、无 Gazebo/MoveIt2 依赖的可复验软件演示。
入口：`roboscientist.adapters.VirtualSimulationAdapter`，通过本地 Web 服务或 CLI 使用。

## 1. 先确认你运行的是什么

本说明中的“虚拟工作台”是仓库内的确定性 Python 模型：固定红色方块、目标区域、
一个转运障碍物和六关节示意轨迹。它可以真实运行代码、生成结构化轨迹、检查安全
事件、评价结果并驱动 P0→P1 反馈；它不是 Gazebo/MoveIt2，也不模拟真实电机、
动力学、相机噪声或机械臂碰撞物理。

每个结果都应保留以下边界字段，评审时按字段解释来源：

```text
data_source=simulation
runtime_status=simulation_runtime_verified
runtime_name=roboscientist.virtual_workcell
runtime_version=1.0.0
engine=python_deterministic
synthetic=true
physical_robot_connected=false
```

当前不需要线下操作机械臂，不需要树莓派、ROS、Gazebo、MoveIt2、厂商 SDK 或
网络摄像头。唯一可选的外部网络调用是 Qwen 规划/反馈接口。

## 2. 环境准备

```sh
cd /path/to/roboscientist
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -p 'test_*.py' -q
```

项目只依赖 Python `>=3.9` 和 `pydantic>=2,<3`。如果没有 `.venv`，也可以用
满足版本要求的 `python3`，但建议在提交前固定解释器和依赖版本。

## 3. 启动 Web 看板

```sh
.venv/bin/python -m roboscientist.web.server \
  --host 127.0.0.1 \
  --port 8010 \
  --data-root data/preview
```

浏览器打开 <http://127.0.0.1:8010/>。端口可改；后续命令中的 `BASE` 应与端口
保持一致：

```sh
BASE=http://127.0.0.1:8010
```

页面默认选中 `Simulation`，并显示“纯 Python 虚拟工作台、不连接实机”。页面中
可看到场景投影、目标方块、障碍物、TCP 轨迹、P0/P1 状态、失败归因和重复验证
指标；这些是本地 JSON 结果，不是实时机械臂视频。

## 4. 启动后先做三项探针

```sh
curl -fsS "$BASE/api/health"
curl -fsS "$BASE/api/config"
curl -fsS "$BASE/api/runtime?mode=simulation"
```

确认：

- `/api/health` 的 `physical_robot` 为 `disabled`；
- `/api/config.virtual_runtime.engine` 为 `python_deterministic`；
- `/api/config.virtual_runtime.gazebo_moveit2` 为 `not_used`；
- `/api/runtime?mode=simulation` 的 `physical_robot_connected` 为 `false`；
- 没有把 `historical_real_arm` 或旧的 `simulation_runtime_unverified` 当作当前运行时。

## 5. 推荐主线：定位偏差 P0→P1

这是最容易看出“反馈改变下一轮计划”的场景。模型在固定场景注入 +20 mm X
方向位置残差，系统只允许修改 `grasp_offset` 参数族。

### 5.1 运行活动

```sh
curl -fsS -X POST "$BASE/api/campaigns" \
  -H 'Content-Type: application/json' \
  -d '{
    "task_text": "把红色方块放到右侧目标区域",
    "scenario": "pose_offset",
    "mode": "simulation",
    "max_rounds": 2,
    "use_qwen": false,
    "auto_run_p1": true
  }' | tee /tmp/roboscientist_campaign.json
```

`use_qwen=false` 是明确的离线确定性模式，不是 Qwen 调用失败后的隐式降级。
响应中记录 `campaign_id`；保存完整 JSON，不要只截图页面文字。

### 5.2 查看活动和单轮证据

```sh
CAMPAIGN_ID=$(python3 -c 'import json,sys; print(json.load(open("/tmp/roboscientist_campaign.json"))["campaign_id"])')
curl -fsS "$BASE/api/campaigns/$CAMPAIGN_ID" \
  | tee "/tmp/roboscientist_campaign_${CAMPAIGN_ID}.json"
```

从返回的 `records` 读取两个 `experiment_id`，再查看：

```sh
curl -fsS "$BASE/api/experiments/<experiment_id>"
```

预期解释：

| 阶段 | 预期现象 | 关键证据 |
|---|---|---|
| P0 | 规划成功但评价发现稳定位置偏差 | `status=failed`、`failure.code=POSE_OFFSET`、`position_error_x_m=0.02` |
| 反馈 | 只选择 `grasp_offset` | `feedback_adjustment.strategy=signed_residual_compensation` |
| 候选 | X 偏移由 `0` 改为约 `-0.02 m` | `candidate_skill.changed_parameter_family=grasp_offset` |
| P1 | 同场景重新执行并消除残差 | `status=succeeded`、`position_error_m=0.0` |
| 条件 | P0/P1 条件没有变化 | `same_condition.verified=true`、`differences=[]` |

一次 P1 通过只代表软件虚拟工作单元中的候选验证；活动仍返回
`promotion=candidate_only`，不能直接写成实机成功率提升或稳定 Skill 晋升。

## 6. 重复验证（建议提交前运行）

每个版本默认运行 10 次，总计 20 次，使用相同任务、场景、评价器和安全约束：

```sh
curl -fsS -X POST "$BASE/api/validation" \
  -H 'Content-Type: application/json' \
  -d '{
    "task_text": "把红色方块放到右侧目标区域",
    "scenario": "pose_offset",
    "mode": "simulation",
    "repeats": 10,
    "use_qwen": false
  }' | tee /tmp/roboscientist_validation.json
```

预期确定性结果：P0 成功率 `0%`、平均位置误差约 `0.020 m`；P1 成功率 `100%`、
平均误差 `0.000 m`；比较决策为 `promote_candidate_for_review`。这只是模型内的
可重复改善证据，仍需保留“合成、非物理、非实机”的限制声明。

若把 `repeats` 改成 `2`，即使 P1 有改善，决策也应是
`candidate_only_insufficient_samples`；这是防止用少量样本过度宣称的保护。

## 7. 其他可演示场景

通过 `/api/campaigns` 的 `scenario` 切换，或在前端选择场景：

| 场景 | 反馈策略 | 预期变化 |
|---|---|---|
| `path_risk` / `path_blocked` | `raise_transit_height` | 中转高度从约 `0.12 m` 提高 `0.01 m`，减少路径风险 |
| `grasp_failed` | `raise_grasp_z` | 抓取偏移 Z 增加约 `0.005 m` |
| `timeout` | `stop_for_human` | 不生成自动候选，活动停止/需人工处理 |
| `collision` | 路径安全拒绝 | 记录障碍物/碰撞事件，不绕过安全门 |
| `success` | 无需反馈 | P0 已成功，通常不执行 P1 |

场景是可控扰动，不是随机噪声实验。若要主张泛化，需要另行设计并冻结多场景
实验矩阵，不能把这些固定分支当成真实机械臂统计。

## 8. 证据文件位置

假设服务以 `--data-root data/preview` 启动：

```text
data/preview/
├── campaigns/<campaign_id>/
│   ├── campaign.json
│   ├── validation.json                 # 调用 /api/validation 后生成
│   └── qwen/                           # use_qwen=true 且有调用时，内容已脱敏
├── experiments/<experiment_id>/
│   ├── plan.json
│   ├── result.json
│   └── analysis.json                   # 有失败分析时生成
├── skills/<skill-version>.json
└── virtual_artifacts/<experiment_id>/
    ├── scene.json
    ├── trajectory.json
    ├── evaluation.json
    ├── execution_trace.json
    ├── replay.json
    └── manifest.json
```

`manifest.json` 包含运行时名称、版本、引擎、`synthetic=true`、
`physical_robot_connected=false` 以及各 JSON 文件 SHA256。`artifacts` 字段中的
路径是服务进程本机路径；`virtual://...` 仅在未配置落盘目录的直接适配器调用中
使用，不是可下载的网络 URL。冻结提交包时应将这些路径转换为包内相对路径，
不要把个人电脑的绝对路径写入 JSON、截图或报告。

## 9. 直接调用 Python 适配器（可选）

需要调试模型而不启动 HTTP 服务时：

```python
from pathlib import Path
from roboscientist.adapters import VirtualSimulationAdapter, VirtualScenario

adapter = VirtualSimulationAdapter(
    VirtualScenario.POSE_OFFSET,
    artifact_root=Path("data/direct_virtual_artifacts"),
)
print(adapter.get_robot_state())
```

正常业务应通过 `DemoApplication`/HTTP API，让 `Orchestrator` 统一完成任务解析、
安全检查、结果存储和候选 Skill 归档。直接调用适配器不会自动生成完整的
`ExperimentPlan`。

## 10. Qwen 可选模式

如确实要展示 Qwen 的科学计划和反馈文本，在启动服务的同一进程设置：

```sh
export DASHSCOPE_API_KEY='只存在于本机环境变量'
export DASHSCOPE_BASE_URL='https://dashscope.aliyuncs.com/compatible-mode/v1'
export QWEN_MODEL='qwen3.7-plus'
export QWEN_TIMEOUT_S='90'
.venv/bin/python -m roboscientist.web.server --port 8010 --data-root data/preview
```

然后将活动请求中的 `use_qwen` 改为 `true`。系统会分别记录 planning 和
adjustment 两阶段的脱敏元数据、模型名、Request ID、Schema 状态和 SHA256；Qwen
只输出 `ScientificPlanDraft`/`FeedbackAdjustmentDraft`，安全门和参数候选仍由
确定性程序控制。

浏览器中的 Qwen 复选框默认关闭，即使本机检测到配置也不会自动发起网络请求；
这样可直接完成离线虚拟演示。勾选前应先确认 `/api/config` 中的模型和账号可用。

如果 key 不存在、模型不可用、网络超时或返回内容无法通过 Schema 校验，接口应
返回结构化 `502` 并停止该活动；不要临时改成 `use_qwen=false` 后把结果说成
Qwen 已调用。不要提交 `.env` 或任何真实 API key。

## 12. 不能由本说明推出的结论

本运行说明不能证明：

1. ArmPi 已连接、运动或抓取成功；
2. Gazebo/MoveIt2 已完成规划、动力学和碰撞验证；
3. 候选 Skill 在真实实验中的成功率提高；
4. 虚拟轨迹是机械臂的最优路径；
5. Qwen 输出替代了安全检查、评价器或原始实验数据。

如未来接入经验证的物理仿真或实机，应保持同一 `ExperimentResult`/证据字段，
新增真实运行时和日志证明，并单独升级数据来源声明；不能仅修改标签把本运行时
伪装成另一种证据。
