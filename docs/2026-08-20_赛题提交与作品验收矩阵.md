# 赛题提交与作品验收矩阵

日期：2026-08-20
适用方向：赛道一，方向 1B，科学实验任务规划与反馈迭代
官方依据：`赛道一-方向1B-科学实验任务规划与反馈迭代-提交要求及模板.docx`

## 1. 产品结论

当前产品方向可以匹配赛题，但不能把“机械臂完成一次抓取”或“失败后更换参数再运行一次”直接视为作品完成。最终作品必须同时证明：

1. 系统围绕一个明确、可证伪的实验问题形成执行前计划；
2. 第一轮真实结果触发了有依据的判断，并改变第二轮计划；
3. 两轮保持评价口径一致，原始结果、失败、人工介入和未改善项均保留；
4. 至少完成一种同条件对照，重复运行结果支持或否定改进主张；
5. Qwen 在规划或反馈环节被真实调用，且关键实验结果不由大模型主观判定；
6. 测试 API、可交互前端、源代码、运行说明和代表案例能够被独立核验。

首个代表案例应收敛为：

> 在固定红色长方体 A→B 抓取场景和相同安全约束下，系统能否根据 P0 的视觉结果与带符号位姿残差，只调整一个参数族生成候选 P1，并在重复实验中改善抓取/放置结果且不增加安全事件？

在取得连续 TCP/TF 轨迹前，不能把关节总行程描述为真实末端路径长度，也不能把本案例主张写成“已得到路径最优解”。

## 3. 科研闭环验收口径

### 3.1 研究问题与假设

- 已有证据：冻结 P0 脚本曾完成一次红色长方体 A→B 抓取；这只证明基线可用，不证明稳定成功率。
- 待检验假设：若 P0 的视觉评估显示稳定、带方向的位置偏差，则在安全范围内应用对应抓取偏移会改善结果。
- 零假设：P1 相对 P0 不产生可重复改善，或改善伴随安全、耗时或其他指标退化。
- 可证伪结果：P1 无改善、结果波动无法区分、失败类型改变、出现安全退化，均应拒绝晋升或转人工判断。

### 3.2 变量与控制

| 类型 | 首个案例要求 |
|---|---|
| 自变量 | 每轮只改变 `grasp_offset` 或 `path_profile` 中一个参数族 |
| 主要因变量 | `task_success_rate`、`grasp_success_rate`、`place_success_rate`、`position_error_m` |
| 次要代价 | 执行耗时、关节总行程、安全事件、人工介入次数 |
| 控制变量 | 方块、A/B 点、光照、相机与标定版本、评价器版本、安全档案、重复次数 |
| 停止条件 | 越界、低置信度、标定无效、软件停止不可用、不可归因失败或达到预设样本数 |

### 3.3 Qwen 与确定性程序的边界

Qwen 可以承担：

- 把自然语言研究目标整理为结构化研究问题和候选假设；
- 在给定证据、允许参数族和安全边界内提出下一轮计划草案；
- 解释 P0→P1 的变化理由、替代解释和仍待验证项；
- 生成面向报告的实验摘要。

Qwen 不得承担：

- 直接判断物体是否抓住、提起或放置；
- 绕过视觉评估器或把动作完成当作实验成功；
- 直接输出舵机 ID、脉宽、底层 ROS 2 指令或越界参数；
- 擅自改变评价口径、固定验证集或安全约束；
- 用自然语言结论覆盖原始数据和确定性统计结果。

每次真实 Qwen 调用至少保存：模型名、调用时间、请求 ID、输入上下文版本、提示词 SHA256、结构化响应、Schema 校验结果和是否被安全层拒绝。API Key 只通过环境变量提供，禁止写入实验包或截图。
