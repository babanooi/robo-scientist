# RoboScientist 硬件能力交付手册

> 版本：v1.1  
> 生效日期：2026-07-15  
> 适用范围：ArmPi Ultra、固定工作台的颜色方块抓取与放置实验。本文只规划硬件侧开发、联调和实验交付，不定义上层业务实现。  
> 首要目标：五位研究生向队长/上层软件交付可直接接入的机械臂能力、结构化接口、样例数据和操作文档。队长不应再研究厂商 GUI，也不应猜测硬件状态、坐标语义或文件位置。  
> 前提：厂商识别、抓取、逆运动学和底层驱动是实验执行底座；团队的系统价值是基于真实实验数据更新参数化抓取轨迹 Skill，并用重复实验决定晋升或回滚。

## 0. 交付定位与事实状态

### 0.1 硬件组的唯一交付对象

硬件组不负责实现 AI Scientist、前端、优化器或业务状态机。其工作结束标准是：队长在不了解厂商 GUI 的前提下，能据此完成 Mock、实机 `Adapter`、确定性安全校验、`ExperimentPlan`/`ExperimentResult`、优化与评估。

每项交接必须包含以下四类产物，缺一不可：

1. Markdown 文档：能力边界、环境/参数、调用方式、限制、恢复步骤和责任人。
2. 结构化接口或样例数据：JSON、ROS2 接口清单或可调用示例的输出，不用截图代替字段说明。
3. 验收证据：命令、原始日志、实验 ID、图像/视频引用、统计或失败记录。
4. 队长用途：明确该输出用于 Mock、Adapter、安全层、Schema、优化、评估或实机部署中的哪一项。

### 0.2 事实状态分层（截至 2026-07-15）

| 类别 | 内容 | 可否作为开发前提 |

| 手册/既有规划声称 | ArmPi Ultra 手册描述树莓派 5 与 STM32 控制链、6 自由度总线舵机、ROS2 工作区和厂商示例；相机/麦克风及视觉能力随套装与配置而异 | 仅可用来安排调查；不得当作已可调用能力 |

### 0.3 开发与部署链路定位

队长主要在本地电脑开发上层智能体、任务规划、Mock、实验日志、优化器和前端；机械臂树莓派侧只运行 ROS2/SDK、相机、控制服务和 `robot_adapter` 实机适配层。默认工作流如下：

```text
队长电脑：上层智能体 / Mock / 看板 / 实验评估
        |
        | SSH、Git、Remote-SSH、HTTP/WebSocket 或 ROS2 网络调用
        v
机械臂树莓派：ROS2/SDK / 相机 / 机械臂控制 / robot_adapter
```

A 必须在 `设备与环境调查.md` 中确认 IP、账号、认证方式、代码目录、Git/Remote-SSH/scp/rsync 是否可用、启动/停止/日志命令和网络限制。若无法稳定部署代码到树莓派，G0 只能判为“受限通过”或“不通过”；不得用手动点击 GUI 替代程序化接入。

## 1. 目标、边界与工作原则

### 1.1 G0 硬件可行性闸门

七天内以可复验的日志、样本和视频证明以下能力；未提供证据不得标记为完成。

1. 不依赖厂商 GUI，能够以程序启动、回零、读取状态、执行关节/末端运动、控制夹爪和安全停止。
2. 能通过 SSH/Git/Remote-SSH/scp 或 rsync 将队长提供的最小适配器代码部署到树莓派，启动后可查看日志并执行自检。
3. 能获取 RGB-D 或等效三维测量数据，输出颜色方块与目标区的相机坐标、置信度和时间戳。
4. 能完成相机坐标到机械臂基座坐标的首版转换，并量化静止目标的重复定位误差。
5. 能按统一的实验 ID 自动保存计划、动作、状态、图像、结果和异常。
6. 能在隔离的固定工作台上连续完成 20 次保守基础动作，且全程可人工急停、超时停止和恢复。

G0 通过后，软件方可在不变更业务逻辑的条件下，将 Mock 适配器替换为实机适配器。G0 未通过不阻塞 Mock 闭环，但不得宣称完成实机自迭代。

### 1.2 不可突破的边界

- LLM 只能产生结构化实验计划和候选参数；它不能生成关节脉冲、绕过安全层或直接调用厂商底层接口。
- 确定性安全层必须在每个动作前验证工作空间、速度、姿态、夹爪范围、超时和场景状态；任一检查失败即拒绝执行。
- 每个候选 Skill 每轮只允许变更一个参数族：坐标残差补偿、抓取点偏移、预抓取高度、接近方向、夹爪时机/宽度或速度。其余参数继承父版本。
- 任何标定、场景、设备或安全配置变化均新建版本；禁止在一次 P0/P1 对比中间静默修改。
- 扭矩、电流和碰撞状态必须调查、记录可用性和采样语义；它们不是 MVP 成功判定或安全联锁的硬依赖。MVP 的安全基线是物理急停、工作空间、保守速度、超时、状态确认和人工监护。

### 1.3 统一约定

| 项目 | 约定 |
|---|---|
| 长度、速度、角度 | `m`、`m/s`、`rad`；面向操作者的报告可同时显示 `mm`、`deg` |
| 坐标系 | `base` 为机械臂基座；`camera` 为相机光学坐标；`tool` 为末端工具；`table` 为工作台；所有位姿必须带 `frame_id` |
| 姿态 | 四元数 `[x, y, z, w]`；不使用未说明顺序的欧拉角 |
| 时间 | UTC ISO 8601 和单调时钟毫秒；所有跨设备数据须有采集/开始/结束时间 |
| 版本 | `device_config_version`、`calibration_version`、`scene_version`、`skill_version` 全部必填 |
| 状态 | `accepted`、`running`、`succeeded`、`failed`、`rejected`、`stopped`、`timed_out` |

## 2. 七天 G0 执行手册

每天下班前由 E 归档原始证据，A-D 在实验日志中填写输入、设备配置、实际结果和异常。白天所有涉及运动的测试均须有一名现场安全监护人。

| 天数 | 当日目标与全体检查点 | A：设备接口与 ROS2 | B：运动控制与安全 | C：视觉与结果判定 | D：标定与测量 | E：实机实验、采集与可靠性 |
|---|---|---|---|---|---|---|
| D1 | 设备、场地和安全基线就绪 | 清点 ArmPi/树莓派/相机版本，跑通官方启动流程；确认 IP、账号、认证方式和远程登录方式 | 标出物理急停、禁入区、保守工作空间和人工接管口令 | 确认 RGB、深度、点云/三维数据的可读路径 | 画出 `base/camera/tool/table` 坐标关系及单位 | 登记设备档期，测量工作台、方块、目标区尺寸并拍布置图 |
| D2 | 程序化控制最小验证 | 以程序完成连接、状态读取、回零、关节运动、停止；验证 Git/Remote-SSH/scp 或 rsync 代码同步；保存命令和日志 | 为每个动作定义速度上限、超时、前置状态与失败恢复 | 采集 10 组静态 RGB-D 样本，记录时间戳和相机参数 | 定义标定板/采样点方案及误差公式 | 建立 `EXP-*` 编号、场景登记和原始数据目录；旁站记录 D2 测试 |
| D3 | 末端与夹爪动作验证 | 验证末端目标运动、开闭夹爪和最终状态回传 | 用低速测试预抓取、下降、提起、回零；验证越界和超时拒绝 | 输出红/蓝/黄方块、目标区的检测结果及低置信度样例 | 固定相机后完成首轮外参/手眼流程，输出转换草案 | 按统一记录模板采集动作、状态、相机帧和视频引用 |
| D4 | 首版测量与结果判定 | 将控制能力封装为统一返回格式，列出与 Mock 的差异 | 固化基础抓取步骤，不调优参数，只验证步骤顺序 | 定义抓取、提起、放置三阶段判据和证据帧 | 对至少 10 次静止目标测量计算均值、标准差、P95 和离群点 | 建立实验包完整性检查，缺任一必填文件即标记无效 |
| D5 | 安全动作链与单次基线 | 完成停止、超时、恢复、状态异常的错误码映射 | 在安全范围内执行一次完整“预抓取-夹取-提起-放置-回零” | 将目标位姿、置信度和阶段结果写入样例结果 | 将相机位姿转换为 `base` 位姿，标注标定版本和残差 | 对首个基线场景执行 5 次，保存失败而非删除失败 |
| D6 | 重复性和故障注入 | 连续运行接口，记录通信/重连/状态丢失行为 | 进行 20 次保守基础动作；测试拒绝不可达、超时和手动停止 | 测试目标丢失、遮挡、深度无效、低置信度拒绝 | 复测定位误差，确认漂移/重标定触发条件 | 汇总 20 次记录、异常清单、现场视频与设备恢复耗时 |
| D7 | G0 评审与联调冻结 | 提交接口清单、调用示例、环境锁定和已知限制 | 提交安全参数表、测试记录、恢复清单和未解决风险 | 提交样本索引、字段清单、阈值与失败样例 | 提交标定 v0、误差报告、可用范围和拒绝阈值建议 | 主持证据审计，冻结场景 v0、数据结构和 G0 结论 |

| S6 | 8/24-8/31 | 锁定设备镜像、依赖和配置 | 冻结现场参数和安全检查单 | 冻结模型/阈值与证据图 | 冻结标定包与精度报告 | 归档数据、彩排并验证备用路径 | 非原开发者可按手册安全准备和停止设备 |

### 3.2 实机接入里程碑

1. **M0（D7）**：G0 结论明确，接口、错误码、坐标系和数据目录冻结为 v0。
2. **M1（S1 末）**：Mock 合同测试通过。相同 `ExperimentPlan` 在 Mock 与实机中均能返回完整 `ExperimentResult`，允许数值不同，不允许字段语义不同。
3. **M2（S2 末）**：场景和标定误差有版本、有统计。软件已能读取真实实验包但仍可独立用 Mock 开发。
4. **M3（S3 末）**：在不手改业务逻辑的前提下，完成一次真实任务到结果的端到端运行。
5. **M4（S4 末）**：P0/P1 对比数据可复算，P1 只修改一个参数族，完成晋升或回滚。
6. **M5（S5-S6）**：实机连续运行、恢复流程、录屏和 Mock 备用路径均演练通过，设备配置与实验数据冻结。

## 4. 统一硬件接口契约

所有接口由实机适配器和 Mock 适配器共同实现。下面是语义契约，不规定 ROS2 Topic、Service 或 Action 的具体名称；A 在 G0 调查中将厂商接口映射到该契约。`/ros_robot_controller/bus_servo/set_position`、舵机 ID、脉宽位置与 `duration` 仅能存在于 A/B 的驱动实现和调查文档，不得出现在上层智能体工具、`ExperimentPlan`、Skill 版本或前端请求中。

### 4.1 通用请求、响应与错误

```json
{
  "request_id": "REQ-20260714-0001",
  "experiment_id": "EXP-20260714-001",
  "issued_at": "2026-07-14T09:00:00Z",
  "timeout_ms": 10000,
  "device_config_version": "armpi-ultra@2026-07-14"
}
```

```json
{
  "request_id": "REQ-20260714-0001",
  "status": "succeeded",
  "error": {"code": "NONE", "message": "", "recoverable": false},
  "started_at": "2026-07-14T09:00:01Z",
  "finished_at": "2026-07-14T09:00:04Z",
  "robot_state": {},
  "artifacts": []
}
```

错误码至少包含：`INVALID_REQUEST`、`DEVICE_UNAVAILABLE`、`NOT_HOMED`、`OUT_OF_WORKSPACE`、`SPEED_LIMIT`、`COLLISION_RISK`、`LOW_CONFIDENCE`、`TARGET_NOT_FOUND`、`IK_FAILED`、`GRIPPER_FAILED`、`TIMEOUT`、`EMERGENCY_STOP`、`STATE_UNAVAILABLE`、`CALIBRATION_INVALID`、`UNKNOWN`。设备厂商错误必须原样保留在 `vendor_error_code`，并映射为上述稳定错误码。

### 4.2 控制与状态接口

| 能力 | 请求关键字段 | 成功返回 | 拒绝/失败条件 |
|---|---|---|---|
| `reset_home()` | `home_profile` | 最终关节状态、`homed_at` | 急停、未连接、回零超时 |
| `get_robot_state()` | 无 | 关节位置/速度、末端位姿、夹爪状态、运动状态、急停状态 | 状态过期或通信失败需明确标记 |
| `move_joints()` | `joint_positions_rad`、`max_speed`、`timeout_ms` | 实际关节终态、轨迹引用、耗时 | 越限、速度超限、状态不允许、超时 |
| `move_to_pose()` | `Pose`、`max_speed`、`motion_profile` | 必须区分 `ik_solution`、`execution_started`、`execution_finished`；返回实际末端位姿、轨迹 URI 与厂商执行错误 | 坐标系错误、IK 失败、工作空间/桌面风险；仅得到 IK 结果时不得返回 `succeeded` |
| `open_gripper()` / `close_gripper()` | 目标开度；若厂商支持则另传力/电流上限 | 目标与实际开度、状态 | 夹爪异常、超时；不支持的力/电流参数返回 `INVALID_REQUEST` |
| `stop()` | `reason` | 停止确认、停止时状态、是否需复位 | 失败必须升级为人工急停流程 |

`RobotState` 必含 `state_timestamp`、`joint_positions_rad`、`end_effector_pose`、`gripper`、`motion_state`、`is_homed`、`estop_active`。若能读取扭矩、电流、碰撞或温度，放入可选 `telemetry` 并说明采样率、单位、有效范围和缺失语义；任何缺失字段不得被解释为“安全”。

### 4.3 视觉与结果判定接口

```json
{
  "scene_id": "SCENE-OPT-01",
  "captured_at": "2026-07-14T09:00:00Z",
  "frame_id": "camera",
  "rgb_uri": "artifacts/.../scene.rgb.png",
  "depth_uri": "artifacts/.../scene.depth.png",
  "camera_info_uri": "artifacts/.../camera_info.json",
  "detections": [
    {
      "object_id": "cube-red-01",
      "class": "cube",
      "color": "red",
      "pose": {"frame_id": "camera", "position_m": [0.12, 0.03, 0.41], "orientation_xyzw": [0, 0, 0, 1]},
      "confidence": 0.94,
      "measurement_valid": true
    }
  ]
}
```

视觉层提供 `capture_scene()`、`detect_objects(scene)`、`get_object_pose(object_id)`、`get_end_effector_pose()`、`evaluate_execution()`。`evaluate_execution()` 必须分别给出 `object_grasped`、`object_lifted`、`object_placed`、每项置信度、判据版本和图像/数值证据。低置信度、目标缺失、深度无效必须返回可执行的拒绝，而不能用上一次位姿静默代替。

### 4.4 标定与测量接口

`transform_camera_to_base(pose, calibration_version)` 返回 `base` 坐标下位姿、协方差或误差估计、标定版本、转换时间和有效性。D 交付的标定包至少包括：相机内参、`camera->base` 变换、采样方法、有效工作范围、误差统计、校验样本、创建人和日期。

测量置信度由数据有效性、深度质量、目标遮挡、标定有效期和重复性共同决定。安全层拒绝阈值须明确为配置值，例如 `measurement_confidence < threshold` 或预测位置落入误差扩张后的工作空间外；阈值在 S3 由 D 提出、B 批准并版本化。

### 4.5 实验计划与结果接口

```json
{
  "experiment_id": "EXP-20260714-001",
  "task_id": "TASK-001",
  "skill_version": "grasp_cube@0.1.0",
  "scene_version": "fixed-bench@0.1.0",
  "calibration_version": "handeye@0.1.0",
  "target": {"class": "cube", "color": "red"},
  "destination": {"zone_id": "right-zone"},
  "parameter_family": "grasp_offset",
  "grasp_parameters": {"approach_height_m": 0.03, "offset_m": [0, 0, 0], "max_speed_mps": 0.05},
  "safety_constraints": {"workspace_profile": "bench-v0", "require_measurement_confidence": 0.85},
  "repeat_index": 1
}
```

`ExperimentResult` 必含计划快照、实际检测位姿、实际执行位姿、动作事件、关节/末端状态引用、三阶段结果、误差指标、耗时、失败阶段/错误码、安全事件、全部版本号和工件 URI。结果状态与错误码必须由适配器/安全层产生，上层只消费并解释它们。

## 5. 必需安全测试与运行规则

### 5.1 进入每次实机实验前

1. E 确认场景版本、桌面无杂物、目标物与目标区位置符合登记、相机固定且无遮挡。
2. A 检查设备连接、状态新鲜度、回零状态、急停可达；B 确认保守速度和工作空间配置已加载。
3. D 执行快速标定校验；不满足阈值时仅允许重新标定，不允许用人工偏移覆盖。
4. C 检查目标与目标区均被检测且置信度达到阈值；否则记录拒绝并结束本次运行。
5. 软件计划先经过确定性校验，再允许适配器调用。现场安全监护人拥有优先停止权。

### 5.2 必测项与通过标准

| 类别 | 测试 | 通过标准 |
|---|---|---|
| 命令校验 | 非法单位、缺失坐标系、关节/速度越界、不可达位姿 | 执行前拒绝，无机械臂运动，记录 `rejected` 与错误码 |
| 空间安全 | 桌面下方、工作空间外、目标区外的运动请求 | 确定性拒绝或安全路径，禁止擦桌/碰撞测试 |
| 超时 | 人为设置极短超时、通信卡顿 | 自动停止或进入明确恢复状态，保留最后状态 |
| 停止与恢复 | 软件 `stop()`、物理急停、复位/回零 | 能立即进入安全状态；恢复步骤有文档且不自动继续原任务 |
| 感知拒绝 | 目标丢失、遮挡、低置信度、深度无效 | 不发起抓取动作，结果记录失败证据 |
| 标定有效性 | 过期、版本不匹配、校验误差超阈 | 阻止自动执行，要求重标定 |
| 重复性 | 保守基础动作 20 次、完整任务 20 次 | 无失控；每次有完整数据；失败按类型归档 |
| 异常恢复 | 动作失败、夹爪失败、状态丢失 | 不盲目重试；进入停止/回零或人工检查流程 |

禁止为了验证“碰撞检测”而主动制造碰撞。若厂商提供碰撞/扭矩/电流阈值，只能在安全范围内做只读验证，并将其作为告警增强项，不替代空间、安全速度、超时和急停。

## 6. 固定场景实验与数据落盘

### 6.1 场景设计

工作台、相机、光照、方块规格和目标区在 MVP 中固定。变化仅通过版本化的场景配置实现，且每次只改变一类因素。

| 场景集 | 目的 | 设计 | 使用规则 |
|---|---|---|---|
| 优化集 | 发现稳定误差、拟合一个参数族 | 5 个预登记方块位置，固定光照、姿态和目标区 | 可用于生成 P1，不可作为晋升唯一依据 |
| 固定验证集 | P0/P1 公平比较 | 与优化集不重叠的 5 个位置；场景配置锁定 | P0/P1 各至少 10 次，期间不调参 |
| 泛化集 | 检验不是对固定点过拟合 | 新位置、一个新 yaw 或一个受控光照档位；只变一类因素 | P1 完成后执行，不参与优化 |
| 安全集 | 验证拒绝与恢复 | 不可达、目标缺失、遮挡、低置信度、标定失效 | 只验证拒绝/停止，不进行强行抓取 |

每个场景配置记录：工作台基准、方块中心的 `table` 坐标、方块颜色/尺寸/姿态、目标区边界、相机/灯光/支架位置、允许误差、操作人和版本。现场若移动相机、灯具或桌面基准，必须创建新 `scene_version`，并重新执行标定校验。

### 6.2 数据包与目录

```text
data/
  scenes/<scene_version>/scene_config.json
  calibrations/<calibration_version>/calibration.json
  experiments/<experiment_id>/
    plan.json
    result.json
    events.jsonl
    robot_state.jsonl
    scene_before.rgb.png
    scene_before.depth.png
    scene_after.rgb.png
    trajectory.json
    video.mp4                 # 可选；不能录制时写明原因
    manifest.json
```

`manifest.json` 记录文件校验、生成时间、设备/场景/标定/Skill 版本和数据完整性状态。任何失败、拒绝、急停或无效实验也必须有 `plan.json`、`result.json` 和原因，不能通过删除失败样本提高成功率。E 维护实验索引，至少含 `experiment_id`、场景集、Skill 版本、参数族、状态、失败码、成功判定、数据路径和人工复核结果。

## 7. 软件侧交付验收标准

硬件组将以下物品交付给软件侧。软件通过这些验收前，禁止将实机接入视为完成。

| 交付 | 软件验收标准 |
|---|---|
| 接口契约与错误码 | Mock/实机对同一合法请求均返回契约字段；拒绝路径亦返回结构化响应，不抛出未处理厂商异常 |
| 设备配置与启动手册 | 非 A 成员可按文档在指定设备上启动、查询状态并安全停止；不能要求手工点击 GUI 完成主流程 |
| 视觉样本与检测结果 | 至少 10 组 RGB-D/检测样本可被软件读取；包含目标缺失、低置信度、深度无效样例 |
| 标定包 | 软件输入相机位姿后获得带 `base` 坐标、版本、置信度/误差的结果；版本不匹配可被拒绝 |
| 动作与安全日志 | 每个动作有请求 ID、起止时间、最终状态、错误码、关键状态与工件引用 |
| 实验包 | 软件无需手工补字段即可生成单轮结果页面和 P0/P1 指标；所有字段可追溯到原始文件 |
| 契约测试记录 | A-E 与软件方共同签字：配置切换仅改变适配器选择，不改变实验计划语义或业务调用顺序 |

## 8. 风险、决策阈值与降级路径

| 风险 | 早期信号 | 处理与降级 |
|---|---|---|
| SDK/ROS2 无法程序化控制 | 仅 GUI 或官方 Demo 可运行 | G0 判定不通过；软件继续 Mock；A 调查官方 API、ROS2 服务或厂商支持，禁止 GUI 自动化伪装成接口 |
| 视觉数据不可读或不稳定 | 无深度、时间戳丢失、频繁低置信度 | 先固定场景和光照，采用厂商可用三维结果；若仍不可量化，实机仅作演示执行，优化闭环留在 Mock，不声称真实视觉优化 |
| 标定误差过大/漂移 | 误差 P95 超出安全/抓取裕量或每日校验失效 | 重新固定相机与标定；缩小演示工作区；将首个优化变量改为可测的抓取偏移，仍须保留标定版本和误差证据 |
| 无可靠抓取成功判定 | 无法区分夹住、提起、放置 | 优先采用三阶段视觉证据；必要时加入人工复核字段，仅用于标注和报告，不能伪称自动判定 |
| 扭矩/电流/碰撞遥测不可用 | 厂商无接口或含义不明 | 记录为“不可用”；保持急停、工作空间、低速、超时和人工监护，不阻塞 MVP |
| 实机不稳定或设备档期不足 | 连续测试失败、恢复慢、预约冲突 | 冻结已验证场景与参数，提前录制真实实验；现场提供实机、录屏、Mock 三条独立路径，并清楚标识数据来源 |
| 偶然成功被误判为优化 | P1 只在优化点成功、样本量不足 | 固定验证集与泛化集分离；每版至少 10 次；不达标必须回滚并保留证据 |
| 安全事件 | 越界、异常停机、状态不一致 | 立即停止批量实验，保留日志；B/A 完成根因和恢复审核前不得继续自动运行 |
