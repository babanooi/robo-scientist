项目方向为挑战杯赛道一方向一 B“科学实验任务规划与反馈迭代”。MVP 是固定场景下颜色方块抓取与反馈优化。当前硬件侧已跑通 Python/ROS2 控制夹爪、读取 1-6 舵机状态、保存 `home.json`、Windows 下载 JSON，但尚未跑通完整实机抓取、视觉定位、标定和真实反馈迭代。

## 4. 第一阶段目标

实现 S0/S1 最小闭环：

```text
文本任务
 -> TaskSpec
 -> ExperimentPlan
 -> SafetyCheck
 -> DeviceAdapter(mock / simulation / real_arm_stub)
 -> ExperimentResult
 -> FailureAnalysis
 -> Candidate SkillVersion
 -> JSON 落盘
```

必须可复现四类场景：

1. 成功执行；
2. 目标定位偏差；
3. 抓取失败；
4. 执行超时。

每个实验结果必须明确：

## 7. 适配器要求

定义统一 `DeviceAdapter` 协议。上层业务只能依赖该协议。

必须实现：

- `MockAdapter`
- `SimulationAdapter`
- `ArmPiAdapterStub`

`SimulationAdapter` 当前优先实现安全骨架和结构化返回。若当前机器没有 ROS2/Gazebo/MoveIt2 环境，不得伪造真实仿真结果，应明确返回 `simulation_runtime_unverified` 或同等状态。后续由研究生在线下虚拟机验证 ROS2 topic/action/service 后，再补真实调用。

`ArmPiAdapterStub` 当前只能显式返回“实机未接入/硬件未验证”，不得尝试真实 ROS2 写操作。

禁止事项：

- 不直接在业务层写 `/ros_robot_controller/bus_servo/set_position`；
- 不在上层暴露舵机 ID、脉宽方向、duration；
- 不把 `/kinematics/*` 当作真实执行成功；
- 不把 Mock 数据伪装成实机数据。
- 不把未实际运行的 Gazebo/MoveIt2 结果伪装成仿真数据。

## 8. 安全层要求

实现确定性安全检查，至少覆盖：

- 是否允许真实机器人；
- 目标置信度阈值；
- 工作空间范围；
- 最大实验时长；
- 参数是否越界；
- 是否缺少标定版本；
- Mock/实机数据源标记。
- Mock/仿真/实机数据源标记。

安全检查失败时，实验不得继续执行，并输出结构化错误码。

## 9. Mock 场景要求

MockAdapter 需要可配置场景结果，至少支持：

| 场景 | 期望结果 |
|---|---|
| `success` | 抓取、提起、放置均成功 |
| `pose_offset` | 定位偏差导致失败，FailureAnalysis 生成抓取点偏移候选 |
| `grasp_failed` | 夹爪或抓取点失败，生成夹爪/抓取参数候选 |
| `timeout` | 动作超时，生成超时错误且不晋升 |

候选版本第一版可以只实现一个参数族，例如 `grasp_offset`，但代码结构要允许后续扩展。

## 9A. 虚拟仿真模式要求

当前主 demo 的目标是升级到 Gazebo/MoveIt2 虚拟仿真闭环。已从官方资料确认的基础命令如下：

```bash
ros2 launch robot_gazebo worlds.launch.py
ros2 launch robot_gazebo worlds.launch.py moveit_unite:=true
ros2 launch armpi_ultra_moveit_config demo.launch.py use_sim_time:=true use_gazebo:=true
```

URDF/Xacro 模型路径线索：

```text
ros2_ws/src/simulations/armpi_ultra_description/urdf/
armpi_ultra.xacro
arm.urdf.xacro
```

开发要求：

- API/CLI/前端支持选择 `mode = "mock"` 或 `mode = "simulation"`；
- `simulation` 模式当前可先返回环境未验证，但必须使用正式 schema；
- 前端必须明确展示 `data_source`；
- 页面文案区分：
  - `mock`：流程模拟；
  - `simulation`：Gazebo/MoveIt2 虚拟仿真；
  - `real_arm`：真实机械臂，未来接入；
- 仿真模式后续应能展示规划成功、碰撞状态、轨迹长度、规划时间、规划器名称、轨迹点和迭代前后指标对比。

## 11. 测试要求

必须使用 `unittest` 或可用本地测试工具覆盖：

1. 文本任务生成 `TaskSpec`；
2. `ExperimentPlan` 字段完整；
3. 安全层拒绝低置信度或越界；
4. Mock 成功场景生成成功 `ExperimentResult`；
5. Mock 定位偏差场景生成候选 Skill；
6. Mock 抓取失败场景生成失败分类；
7. Mock 超时场景不会晋升；
8. Mock 结果必须标记 `data_source = "mock"`。
9. SimulationAdapter 在 ROS2/Gazebo 环境未验证时返回明确状态，不生成伪造 `simulation` 轨迹。

运行命令建议：

```bash
python -m unittest
```

## 13. 成功标准

S0/S1 判定为完成的最低标准：

- 不依赖真实机械臂即可端到端运行；
- 四类 Mock 场景可复现；
- 代码结构支持 `mock/simulation/real_arm_stub` 三种执行模式；
- 仿真模式有正式 schema 和安全未验证返回；
- 每次实验有 `plan.json` 和 `result.json`；
- 能生成候选 Skill 或明确拒绝；
- 有测试覆盖；
- 代码中没有把厂商 ROS2 接口泄漏到业务层；
- README 或命令说明能让主会话复跑。
