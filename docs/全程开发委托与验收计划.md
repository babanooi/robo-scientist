# RoboScientist 全程开发委托与验收计划

版本：v0.1
日期：2026-09-05
适用范围：在当前仓库和已有资料基础上，尽量由软件侧完成作品开发、验证和提交材料整理。

## 1. 先说结论

软件侧可以代为完成：代码实现、接口设计、前端页面、虚拟闭环、测试、运行脚本、实验记录模板、提交包和答辩材料。
软件侧不能替代：机械臂现场接线/操作、真实传感器采集、物理安全监护、比赛账号授权，以及官方要求的真实仪器或 Gazebo/MoveIt2 证据。

因此“完成全部开发”应定义为：在已授权的软件和虚拟环境内完成一个可复现、可调用、可交互的作品候选包；是否达到官方完赛，还要由赛题验收口径和所需运行环境决定。

## 2. 软件侧默认交付范围

1. 任务输入：文本/语音转写结果的统一任务结构。
2. 任务规划：约束解析、P0 计划、参数化 P1 候选和安全前置检查。
3. 执行适配：mock、纯 Python 确定性虚拟工作单元，以及预留的 real-arm/bridge 契约。
4. 反馈闭环：执行记录、结果评价、失败分析、下一轮参数建议和人工接管状态。
5. 证据链：campaign、experiment、Qwen 脱敏元数据、轨迹/评价/manifest 和哈希。
6. 访问入口：HTTP API、交互式 Web 页面、停止/接管控件和状态展示。
7. 质量保障：离线测试、API smoke test、复现命令、提交说明、演示脚本和 PPT 提纲。

## 3. 需要用户最少参与的事项

这些事项不能安全地替用户自动决定：

- 确认作品名称、队伍信息、最终演示场景和提交渠道；
- 明确是否允许使用 Qwen，以及在本机以环境变量提供 API key（密钥不得进入 Git）；
- 确认官方是否强制 Gazebo/MoveIt2 或实机，及其截止时间；
- 在需要真实设备时，由现场人员完成上电、急停监护、网络连通和最终 P0/P1 运行；
- 对最终提交包做一次人工浏览和授权发布。

除以上事项外，软件侧可按本计划持续推进，不要求用户逐行编程。

## 4. 里程碑和可验收产物

### M0：范围冻结

验收：`README`、PRD、提交限制声明和本计划对数据来源口径一致。
产物：冻结的目标模式（纯软件虚拟 / Gazebo / 实机）、风险清单和提交目录。

### M1：软件闭环可运行

验收：本地 API 能创建 campaign，产生 P0 记录；失败时能生成分析并提出 P1 候选。
产物：代码、配置、测试日志、API 请求/响应样例。

### M2：反馈迭代可观察

验收：前端能展示 P0→反馈→P1，明确显示 `data_source`、运行时状态、评价结果和限制。
产物：演示录屏/截图、campaign JSON、experiment JSON、artifact manifest。

### M3：模型证据接入（可选但建议）

验收：一次真实 Qwen 规划调用和一次反馈调用均有脱敏 request/response 元数据、模型名、Request ID、Schema 校验结果和 SHA256。
产物：`qwen/` 证据目录；无 key、无敏感数据。

### M4：运行时升级（按官方要求选择）

验收：

- 纯 Python 路线：声明为 `simulation_runtime_verified`，不得称为 Gazebo/MoveIt2 或实机；
- Gazebo/MoveIt2 路线：在指定环境中可重复启动、规划、碰撞检测、执行和回取轨迹；
- 实机路线：硬件 bridge、wrapper、评价器、急停和同条件重复实验全部通过。

### M5：提交冻结

验收：固定 Git commit 可重跑；`SHA256SUMS.txt` 校验通过；材料中的每个结论都能追溯到证据。
产物：源码包、运行说明、API 文档、前端入口、测试日志、演示脚本、PPT/PDF 和限制声明。

## 5. 不能提前承诺的结论

在没有同条件重复实验和原始评价证据前，不得写成“路径最优”“成功率提升”“机械臂已自主完成抓取”或“Gazebo/MoveIt2 已验证”。纯软件虚拟工作单元只能证明软件逻辑和闭环可复现。

## 6. 当前仓库基线（截至本版本）

- 离线测试：124 个测试通过（以最终冻结提交重新运行的日志为准）；
- 已有：Web/API、Qwen 结构化调用接口、虚拟工作单元、证据校验器、提交材料模板；
- 未证明：ArmPi 在线连接、Gazebo/MoveIt2 真实运行、物理抓取成功率提升；
- 详细边界见 [提交限制声明_无实机](提交限制声明_无实机.md) 和 [提交包说明_无实机路线](提交包说明_无实机路线.md)。

## 7. 最小决策清单

用户只需回复以下四项即可继续自动推进：

1. 目标运行路线：纯软件虚拟、Gazebo/MoveIt2，还是实机；
2. 是否允许使用 Qwen（允许则在本机配置 key）；
3. 官方验收是否明确要求真实仪器/仿真运行时；
4. 最终提交截止时间和提交平台。

若暂时无法确认，默认按“纯 Python 虚拟闭环 + 诚实限制声明”继续开发，不生成任何伪造实机证据。
