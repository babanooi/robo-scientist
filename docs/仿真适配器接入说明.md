# SimulationAdapter 接入说明

`SimulationAdapter` 是保留的 legacy Gazebo/MoveIt2 适配器契约，数据源固定为
`simulation`。当前公共演示主线使用仓库内的
`VirtualSimulationAdapter`（见[纯 Python 虚拟工作台运行说明](虚拟工作台运行说明.md)）；
不要把下面的未验证状态与公共虚拟工作台的
`simulation_runtime_verified` 混用。两种适配器都与 `MockAdapter` 使用相同的上层
计划、SafetyCheck、ExperimentResult、FailureAnalysis 和 Skill 存储路径，但不向真实
舵机发出指令。

## 当前状态

本开发环境未验证 ROS2、Gazebo 或 MoveIt2。因此适配器当前返回：

- `hardware_status: simulation_runtime_unverified`
- `planning_success: false`
- `execution_success: false`
- `collision_detected: null`
- 安全事件和失败原因，说明运行时尚未验证

这些字段是运行时状态，不得写入“仿真已经执行”或“机械臂成功抓取”的结论。

## 待虚拟机验证的官方启动线索

在含官方工作区和模型资源的虚拟机/机器人环境中，由硬件组确认以下命令、包名、模型路径和 Action/Topic/Service 契约：

```sh
ros2 launch robot_gazebo worlds.launch.py
ros2 launch robot_gazebo worlds.launch.py moveit_unite:=true
ros2 launch armpi_ultra_moveit_config demo.launch.py use_sim_time:=true use_gazebo:=true
```

模型路径线索为 `ros2_ws/src/simulations/armpi_ultra_description/urdf/`，核心文件为 `armpi_ultra.xacro` 和 `arm.urdf.xacro`。这些路径和命令尚未在本仓库机器执行，不应被上层业务代码硬编码为控制入口。

## 接入完成条件

1. 验证 MoveIt2 的规划请求、轨迹返回、执行完成和取消/停止语义。
2. 将真实返回映射为 `SimulationExecutionData`：规划成功、执行成功、碰撞、规划器、规划耗时、轨迹长度、轨迹点、日志引用和安全事件。
3. 只有在仿真运行时返回真实动作完成证据后，才实现 `SimulationAdapter.execute_pick_place()` 的 ROS2 调用。
4. `RealArmAdapter` 仍须单独实现，不能复用仿真控制路径。
