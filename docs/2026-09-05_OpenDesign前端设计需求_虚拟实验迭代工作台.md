# RoboScientist 前端设计需求文档

**供 OpenDesign 使用｜版本 v1.0｜2026-09-05**

## 0. 文档用途

本文档是 RoboScientist 当前版本的前端设计 brief，供 OpenDesign 产出视觉方案、
页面原型、交互原型和设计规范。设计目标不是做一个普通的“机械臂控制面板”，而是
让评委在几十秒内看懂：

> 系统先执行一轮实验，读取结构化结果，定位失败原因，只修改一个参数族，再在
> 相同条件下验证下一轮方案是否改善。

前端必须同时表现两个核心对象：

1. **机械臂虚拟工作单元**：展示方块、目标区、障碍物、末端轨迹和动作阶段；
2. **实验数据迭代链**：展示 P0 失败、证据归因、参数变化、P1 验证和重复统计。

这是一份设计需求，不要求 OpenDesign 重新设计后端逻辑。所有页面应优先适配当前
已有 HTTP API 和数据结构，不能为了视觉效果虚构后端没有返回的实时视频、关节数据
或真实实验结论。

## 1. 产品事实与证据边界（必须遵守）

### 1.1 当前主路线

当前作品是**纯软件、纯 Python、确定性虚拟工作单元**，固定演示任务为：

```text
把红色方块放到右侧目标区域
```

主演示场景为 `pose_offset`：

- P0：虚拟评价器注入可重复的 X 方向位置残差，结果失败；
- 反馈：根据带符号残差，只调整 `grasp_offset` 参数族；
- P1：继承相同任务、场景、安全约束和评价器，结果成功；
- 重复验证：P0/P1 各 10 次，显示完成率、位置误差、安全/碰撞指标。

### 1.2 页面常驻的来源标识

以下信息必须在页面顶部或动作画面附近常驻显示，不能藏在设置页：

```text
data_source=simulation
runtime_status=simulation_runtime_verified
runtime_name=roboscientist.virtual_workcell
engine=python_deterministic
synthetic=true
physical_robot_connected=false
```

建议用户可见文案：

- `SIMULATION · 虚拟工作台`
- `纯 Python 可复验运行时`
- `非实机 · 不发送底层运动命令`
- `结果不代表真实机械臂或 Gazebo/MoveIt2 验证`

### 1.3 不得出现的误导

设计中禁止：

- 把二维轨迹绘制成“真实相机直播”或“机械臂实时视频”；
- 使用“实机已连接”“抓取成功率已提升”等未经证据支持的文案；
- 把纯 Python 运行时标成 Gazebo、MoveIt2、ROS 或物理动力学仿真；
- 把 `use_qwen=false` 的确定性流程写成真实 Qwen 调用；
- 用一条成功轨迹暗示“全局最优路径”；
- 在暂无数据时画假轨迹、假关节曲线或假传感器数值。

## 2. 设计目标与评审叙事

### 2.1 首屏 10 秒目标

用户进入页面后，应立即知道：

1. 这是一个面向科学实验闭环的机械臂智能体；
2. 当前是 Simulation，而不是实机；
3. 左侧/主视觉区域可以看到虚拟工作台和轨迹；
4. 系统能把 P0 失败反馈到 P1，而不是只执行一次动作。

### 2.2 90 秒演示叙事

页面交互应支持以下讲解顺序：

1. 输入自然语言任务；
2. 选择 Simulation 和定位偏差场景；
3. 运行 P0→P1 闭环；
4. 看到 P0 失败及 `POSE_OFFSET`；
5. 看到唯一参数族从 `grasp_offset=0` 改为 `-0.020 m`；
6. 看到 P1 在相同条件下成功；
7. 运行 10×10 重复验证；
8. 看到任务完成率从 `0.0` 变为 `1.0`，位置误差从 `0.020 m` 变为 `0.000 m`；
9. 看到安全事件和碰撞率没有增加；
10. 看到候选仍是 `candidate_only`，需要人工复核后晋升。

### 2.3 设计关键词

`evidence-first`、`closed-loop laboratory`、`industrial editorial`、
`auditable motion`、`scientific comparison`、`calm but high-signal`。

## 3. 推荐视觉方向

### 3.1 概念方向

**“证据优先的工业实验室控制台”**。

它应像一个用于实验记录和复核的仪器控制台，而不是消费级机器人 App 或聊天机器
人。视觉上兼顾实验室的严谨、机械系统的结构感和数据产品的清晰度。

### 3.2 色彩建议

使用高对比、低饱和的工业色，不使用紫色渐变或泛 AI 霓虹风：

| 语义 | 建议色 | 用途 |
|---|---|---|
| 主墨色 | `#17231F` | 标题、边框、主要按钮 |
| 暖纸底 | `#E8E9DF` | 页面背景、实验记录感 |
| 信号红 | `#BA402D` | P0 失败、风险、异常、停止 |
| 成功绿 | `#24684F` | P1 成功、安全通过、证据完整 |
| 警告黄 | `#9D6419` | candidate、待人工复核、样本不足 |
| 信息蓝 | `#245D73` | 研究问题、同条件说明、辅助信息 |
| 数据白 | `#FBFBF5` | 卡片、表格、图表底色 |

颜色不能单独承担状态含义；必须同时配合文字、图标或形状。

### 3.3 字体建议

- 中文标题/正文：思源黑体或同等可读的中文无衬线字体；
- 英文标题：可用具有编辑感的窄体/人文无衬线字体；
- ID、版本、坐标、SHA256、状态码：`IBM Plex Mono`、`JetBrains Mono` 或同类等宽字体；
- 避免 Arial、Roboto、Inter 作为唯一字体；
- 正文最小字号建议 13px，数据标签可用 10–11px，但必须保证对比度。

### 3.4 形状与材质

- 默认少圆角或直角，体现仪器面板和实验记录；
- 用细网格、刻度线、坐标轴、编号和分隔线制造“工作台”感；
- 不使用过度玻璃拟态、漂浮卡片和大面积渐变；
- 允许在虚拟工作台中使用轻微扫描线/网格动画，但不能遮挡轨迹和文字。

### 4.2 页面分区优先级

| 优先级 | 区域 | 目的 |
|---|---|---|
| P0 | 虚拟工作台 + P0/P1 闭环时间线 | 第一眼证明系统在“实验—反馈—再实验” |
| P0 | P0/P1 指标对照 + 参数差异 | 证明数据改变了下一轮计划 |
| P1 | 实验配置、科学问题、假设 | 说明这是科学实验而非按钮控制 |
| P1 | 重复验证统计 | 说明改善不是单次偶然结果 |
| P1 | 运行时/安全状态 | 建立可信边界，防止误解为实机 |
| P2 | Qwen 审计、硬件证据门、技术 JSON | 供评审复核，不抢主叙事 |

## 5. 核心页面与组件需求

### 5.1 顶部状态栏（Masthead）

显示：

- 产品名：`RoboScientist`；
- 中文标题：`机械臂科学实验闭环控制台`；
- 副标题：`规划、执行、观测与反馈迭代的可审计工作台`；
- 当前总状态：空闲、运行中、已记录 2 轮、需要人工复核等；
- 停止/接管按钮。

停止按钮在当前 Simulation 主流程中应显示为“未来实机边界”或禁用状态，不能让用
户误以为点击会停止真实机械臂。

### 5.2 来源横幅（Source Banner）

这是全页面最重要的信任组件之一。

推荐结构：

```text
[SIMULATION · 虚拟工作台]
项目自带纯 Python 虚拟工作单元；结果不代表真实机械臂或 Gazebo/MoveIt2 验证。

Qwen · 未调用 / 已记录       虚拟运行时 · 就绪       物理机械臂 · 未就绪
```

点击或悬停可展开技术字段，但默认不能隐藏 `非实机` 说明。

### 5.3 虚拟工作台（主视觉区域）

#### 必须呈现的元素

- 工作台边界和坐标轴；
- 红色方块（目标物）；
- 右侧目标区域；
- 转运障碍物；
- 起点、当前末端位置和终点；
- TCP 轨迹采样点与方向箭头；
- 当前场景：`pose_offset`；
- 采样点数、状态和安全事件；
- `data_source=simulation`、`physical_robot=false`。

#### 轨迹编码

| 状态 | 轨迹颜色/样式 | 解释 |
|---|---|---|
| P0 失败 | 信号红、虚线或带失败节点 | 基线方案，显示失败位置/阶段 |
| P1 候选 | 成功绿、实线 | 反馈调整后的方案 |
| 当前候选待复核 | 警告黄边框 | 已执行但尚未晋升 |
| 路径风险/碰撞 | 红色高亮 + 斜线障碍区 | 安全门阻止或标记风险 |

#### 高度表达

当前是二维投影，不要伪装成三维物理仿真。可采用：

- x/y 平面主视图；
- 轨迹点的透明度、点大小或旁侧高度条表达 z；
- 小型侧视剖面显示“抬升”阶段；
- 明确标注：`二维投影：x / y；高度 z 通过抬升显示`。

#### 空态

实验尚未运行时显示真实空态：

```text
SIMULATION / READY
等待虚拟实验
运行 P0 或 P0→P1 闭环后，这里显示实际返回的场景与轨迹。
```

不要在空态放置一条装饰性假轨迹。

### 5.4 运行时与安全状态卡

右侧显示五个状态块：

1. 数据来源：`Simulation / 虚拟工作台`；
2. Bridge：`已就绪`（表示软件服务，不表示机械臂连接）；
3. 运动状态：`idle / planning / executing`；
4. 预检：`未执行 / 已通过 / 被拒绝`；
5. 停止/接管：`仅实机`。

每个状态块都要有第二行解释，例如：

```text
运动状态：idle
本地虚拟执行；不发送机械臂命令
```

### 5.5 实验配置区

控件：

- 任务文本框，默认值：`把红色方块放到右侧目标区域`；
- 数据来源模式：
  - `Simulation 纯 Python 虚拟工作台`（默认、主入口）；
  - `Mock 软件流程验证`（次入口）；
  - `Real Arm 实机证据`（当前禁用/边界说明）；
- 场景：
  - `定位偏差`（主演示）；
  - `路径风险`；
  - `抓取失败`；
  - `执行超时`；
  - `任务成功`；
- Qwen 开关：默认关闭；未配置时禁用并显示原因；
- 主按钮：`运行 P0 → P1 科研闭环`；
- 次按钮：`仅运行 P0（诊断）`；
- 重置按钮：`重置 P0 条件`。

控件附近必须提示：

```text
闭环运行会固定任务、场景、目标位姿、标定和评价方式；反馈只允许修改一个参数族。
```

### 5.6 科学问题与假设卡

运行后展示：

- 研究问题：
  `在固定场景下，调整一个抓取参数族能否改善 redcube 从当前位置到 right 的任务完成率？`
- 可检验假设：
  `根据上一轮的结构化失败证据，只调整与失败阶段对应的一个参数族可降低残差或失败率。`
- Campaign ID；
- 闭环分类；
- 数据来源；
- 场景；
- 评价器版本；
- 安全检查；
- 当前结论。

空态应写“等待规划”，不显示伪造的模型回答。

### 5.7 五步闭环时间线

这是页面的叙事核心，建议占用整行宽度：

```text
01 规划/假设 →  P0 安全执行  →  03 结果评价  →  04 反馈决策  →  P1 同条件验证
```

每个节点包含：编号、标题、简短结果、状态颜色、关联实验 ID。

状态：

- `WAIT`：尚未开始；
- `RUNNING`：正在执行；
- `ALERT`：P0 失败/发现风险；
- `ACCEPT`：反馈策略通过并执行 P1；
- `CANDIDATE`：P1 成功但尚未晋升；
- `REJECT` / `STOP`：安全或证据门拒绝。

推荐动画：节点依次点亮，失败节点短暂闪烁，参数 diff 从 P0 节点流向 P1 节点。
动画必须支持“减少动态效果”系统设置。

### 5.8 反馈决策卡

P0 失败后突出显示：

```text
失败码：POSE_OFFSET
失败阶段：grasp
观测：virtual evaluator measured a repeatable signed position residual

反馈策略：signed_residual_compensation
允许修改的参数族：grasp_offset
```

参数差异用 diff 组件呈现：

```text
grasp_offset
[0.000, 0.000, 0.000] m  →  [-0.020, 0.000, 0.000] m
```

必须强调“只改一个参数族”，可用左侧单一变更标记和锁图标表达。

### 5.9 P0/P1 实验谱系

用垂直或横向 lineage 展示两轮不会互相覆盖：

| 版本 | 状态 | 关键字段 |
|---|---|---|
| P0 · 基线 | 失败 | experiment_id、失败码、轨迹、失败阶段 |
| P1 · 候选验证 1 | 成功 | experiment_id、候选版本、轨迹、结果 |

每轮可展开查看计划、动作阶段、评价结果和证据引用。不要只显示“成功/失败”两个
大数字而隐藏依据。

### 5.10 同条件对照与指标比较

#### 单次链路对照

显示：

- 条件是否一致：`一致` / `禁止比较`；
- 任务、场景、目标、标定、评价器是否继承；
- P0/P1 实验状态；
- 位置误差；
- TCP/仿真路径；
- 执行时间；
- 安全事件。

#### 重复验证对照

默认 P0/P1 各 10 次。主指标按视觉层级排列：

1. **任务完成率**（最大、最醒目）；
2. **位置误差均值**；
3. **碰撞率 / 安全事件**（硬约束，不能退化）；
4. 路径长度、执行时间（仅报告指标，不标成“最优”）。

建议同时提供：

- P0/P1 并排表格；
- 完成率对比条形图；
- 误差变化箭头；
- 安全指标锁定徽章；
- 样本数 `10 / 10`。

主演示固定示例数据：

```text
P0 任务完成率 0.0       P1 任务完成率 1.0
P0 位置误差 0.020 m     P1 位置误差 0.000 m
P0 碰撞率 0.0           P1 碰撞率 0.0
```

结论文案：

```text
达到内部重复验证门槛：建议人工复核后再晋升
data_source=simulation · 该统计不是实机成功率
```

### 5.11 历史轨迹回放

只读回放可展示：

- 关节位置随时间曲线；
- 5 个动作阶段：接近目标、夹爪闭合、提起、中转移动、放置；
- 轨迹点数、路径长度、执行时间、安全事件；
- 播放阶段按钮。

回放按钮旁必须有：

```text
当前实验记录 · 只读展示，不发送运动命令
```

没有轨迹数据时显示“暂无证据”，不绘制模拟占位线。

### 5.12 Qwen 审计区域

分为“科学规划”和“结果反馈”两张卡，字段：

- 状态：未调用 / 已记录 / 调用失败；
- 模型名；
- Request ID；
- Prompt SHA256；
- Schema 校验状态。

当前默认状态：

```text
确定性规划（未调用 Qwen）
密钥不会写入证据
```

不展示 API Key，不把确定性规划器命名为 Qwen。

### 5.13 硬件基线与证据门

当前项目不接实机，因此该区域应是低优先级、只读、可折叠的“未来接入”面板：

- 显示文档化硬件参数快照；
- 显示 `当前实机验证：否`；
- 显示证据包“未配置”或校验结果；
- 明确“参数存在 ≠ 当前实机已验证”；
- 不提供任何会触发机械臂运动的按钮。

## 6. 交互状态设计

### 6.1 状态矩阵

| 页面状态 | 主视觉 | 时间线 | 对照区 | 可用操作 |
|---|---|---|---|---|
| 初始空态 | 空工作台提示 | 全部 WAIT | 空态说明 | 编辑任务、运行 P0/P1 |
| P0 运行中 | 轨迹逐步绘制 | 规划/执行 RUNNING | 加载中 | 允许安全停止（虚拟不发运动） |
| P0 失败 | 红色失败路径/节点 | 结果评价 ALERT | 显示失败证据 | 查看分析、运行闭环 |
| 反馈已生成 | P0 与候选 diff | 反馈 ACCEPT/CANDIDATE | 单次对照可见 | 执行 P1、重置 |
| P1 成功 | 绿色候选路径 | P1 COMPLETE | 条件一致 | 运行 10×10 验证 |
| 验证完成 | 保留最终轨迹 | 全链路 COMPLETE | 统计表/决策 | 查看证据、重新开始 |
| 安全拒绝/超时 | 路径冻结、警示 | REJECT/STOP | 禁止比较 | 返回人工处理 |
| 服务错误 | 保留上一次数据 | ERROR | 显示错误码 | 重试查询，不清除证据 |

### 6.2 反馈动画

动画只服务于因果关系：

1. P0 轨迹绘制到抓取点；
2. 失败节点落下红色标记；
3. 带符号残差从结果卡移动到参数 diff；
4. P1 轨迹以绿色绘制；
5. 指标卡出现“改善/未退化”标记。

建议时长：单段 300–800ms，总演示动画不超过 3 秒。禁止无限循环、自动滚屏或把
动画速度当作真实机械臂执行速度。

### 6.3 错误与空态文案

错误文案必须告诉用户下一步，不要只显示“Something went wrong”。例如：

```text
暂无可验证轨迹
当前响应未包含 trajectory 或 replay 数据，页面不会绘制虚构路径。
```

```text
Qwen 未调用
当前使用 deterministic-only 模式；不会把本轮结果写成真实模型证据。
```

## 7. 数据与 API 对接要求

设计稿中的组件命名尽量对应以下字段，便于研发直接实现。

### 7.1 初始化查询

| API | 用途 |
|---|---|
| `GET /api/health` | 服务状态、物理设备禁用边界 |
| `GET /api/config` | Qwen 状态、重复验证门槛、虚拟运行时 |
| `GET /api/runtime?mode=simulation` | 运行时、场景、关节状态、连接边界 |
| `GET /api/replay` | 只读历史回放列表 |
| `GET /api/hardware/baselines` | 文档化硬件基线 |
| `GET /api/hardware/evidence` | 只读硬件证据包校验 |

### 7.2 主操作

```json
POST /api/campaigns
{
  "task_text": "把红色方块放到右侧目标区域",
  "scenario": "pose_offset",
  "mode": "simulation",
  "max_rounds": 2,
  "use_qwen": false,
  "auto_run_p1": true
}
```

响应中前端重点读取：

- `campaign_id`、`status`、`classification`、`planning_mode`；
- `scientific_plan`；
- `feedback_adjustment`；
- `records[]`（P0/P1 的 `plan`、`result`、`analysis`、`candidate_skill`）；
- `decision`、`same_condition`、`promotion`；
- `qwen` / `qwen_evidence`。

### 7.3 重复验证

```json
POST /api/validation
{
  "task_text": "把红色方块放到右侧目标区域",
  "scenario": "pose_offset",
  "mode": "simulation",
  "repeats": 10,
  "use_qwen": false
}
```

前端重点读取：

- `repeats_per_version`；
- `summary.p0` / `summary.p1`；
- `task_success_rate`；
- `position_error_mean_m`；
- `collision_rate`；
- `path_length_mean_m`、`execution_time_mean_s`；
- `comparison.decision`、`comparison.deltas`。

### 7.4 仿真轨迹字段

支持从 `result.simulation` 或 replay 工件读取：

- `runtime_name`、`runtime_version`、`engine`；
- `scene_objects`；
- `joint_trajectory`；
- `tcp_trajectory`；
- `trajectory_points`；
- `collision_detected`；
- `safety_events`；
- `evaluation`；
- `physical_robot_connected=false`。

### 7.5 只读详情

设计稿要为以下详情抽屉/弹窗预留入口：

- `GET /api/campaigns/{campaign_id}`；
- `GET /api/campaigns/{campaign_id}/validation`；
- `GET /api/experiments/{experiment_id}`；
- `GET /api/replay/{run_id}`。

## 8. 响应式与可访问性

### 8.1 断点

- `≥1200px`：双列工作台 + 双列数据区；
- `768–1199px`：工作台上下堆叠，时间线允许横向滚动；
- `<768px`：单列，先显示来源、虚拟工作台、闭环时间线，再显示详情；
- 不能仅依赖 hover 才能读取失败原因或来源标识。

### 8.2 可访问性

- 所有状态颜色同时有文字和图标；
- SVG 轨迹有可读的 `aria-label` 和文本摘要；
- 按钮、单选框、复选框可键盘操作；
- 动画支持 `prefers-reduced-motion`；
- 表格使用真正的表头和行列关系；
- 错误状态使用 `aria-live` 通知；
- 文字对比度符合 WCAG AA；
- 不用极细字体显示关键数据。

## 10. 验收标准

OpenDesign 方案满足以下条件才算通过：

- [ ] 首屏明确显示 Simulation、虚拟工作台和非实机边界；
- [ ] 主视觉能看出方块、目标、障碍物和运动轨迹；
- [ ] P0 失败原因和 P1 参数变化在同一视线范围内可关联；
- [ ] 页面明确表现“只修改一个参数族”；
- [ ] P0/P1 条件一致性有独立视觉组件；
- [ ] 重复验证区突出任务完成率和安全硬约束；
- [ ] 路径长度/耗时没有被标成“最优”或唯一目标；
- [ ] 空态不包含假轨迹、假视频或假传感器数据；
- [ ] Qwen 未调用时不会出现模型已执行的暗示；
- [ ] 硬件参数区明确只读、未验证、不触发运动；
- [ ] 桌面、平板、手机布局均能完成主演示路径；
- [ ] 所有关键数据都能追溯到 API 字段或证据工件；
- [ ] 原型能够完整演示 P0→反馈→P1→重复验证。

## 11. 可直接发送给 OpenDesign 的任务描述

```text
请为 RoboScientist 设计一个“证据优先的工业实验室控制台”前端，而不是普通的
机械臂控制面板或聊天机器人页面。

产品核心故事：用户输入“把红色方块放到右侧目标区域”，系统在纯 Python 确定性
虚拟工作单元中执行 P0；虚拟评价器发现可重复的定位偏差，系统根据失败证据只修改
grasp_offset 参数族；随后在相同任务、场景、安全约束和评价器下执行 P1；P1 成功后

   轨迹；P0 使用红色失败轨迹，P1 使用绿色候选轨迹；明确这是二维投影，不是相机直播；

一个可点击原型，能够完整演示 Empty → P0 failed → Feedback diff → P1 success →
Validation result。设计稿中的组件和字段请尽量对应现有 API：/api/config、
/api/runtime?mode=simulation、/api/campaigns、/api/validation、/api/replay。
```
