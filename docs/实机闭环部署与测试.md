# RoboScientist 实机闭环部署与测试

本仓库已提供上层应用、网页、实验归档、候选 Skill 生成和树莓派 HTTP 桥接。首轮目标是固定工作台中的颜色方块抓取/放置。一次真实闭环必须使用 `data_source=real_arm`，并且每轮留下计划、动作、结果、失败证据和 Skill 版本；`mock` 或桥接 `dry_run` 数据不得用于实机结论。

## 放行边界

仓库不能替代现场安全确认。真实动作仅在以下四项同时成立时发生：

1. 场地已清空，底座固定，急停/断电可达，并有人现场监护；
2. `configs/real_arm_profile.local.json` 已填写当前设备的工作空间、标定版本和目标位姿，且 `allow_real_robot`、`motion_enabled` 均为 `true`；
3. 树莓派桥接服务以 `--allow-real-motion` 和已验证后端启动；
4. 上层进程显式带有 `ROBO_ALLOW_REAL_ARM=1`。

任意一项缺失时，系统应返回 `rejected`，而不是运动。

## 硬件组一次性工作

最新红色长方体成功基线运行在 `ubuntu` 用户环境，推荐入口是 `~/armpi_tasks/run_final_dynamic_pick_place.sh`。仓库已提供 `armpi_final_wrapper_backend.py` 将它接到桥接合同。旧 `armpi_backend.py` 只保留给确实存在 `/home/ubuntu/my_armpi` 高层函数模块的环境，不再作为当前设备默认方案。完整合同见 [BACKEND_CONTRACT.md](../roboscientist/hardware_bridge/BACKEND_CONTRACT.md)。

后端必须做到：

- `preflight` 依据当前实机状态、工作空间、速度、急停状态和现场配置决定是否批准；
- `execute_pick_place` 内部完成已批准的抓取动作并返回非空 `actions`、`outcome`、失败码、执行耗时和工件 URI；只有取得 TF/TCP 数据后才能返回米制末端路径长度；
- `PATH_BLOCKED`、`POSE_OFFSET`、`GRASP_FAILED`、`TIMEOUT` 等失败要由实机测量产生；
- `stop` 调用当前设备最快且已验证的停止方式；
- 不得向上层 JSON 暴露 ROS2 topic、舵机 ID 或脉冲值。

当前 wrapper 会在 check 和 pick-place 时重新执行动态视觉链。配置中的 `target_pose` 只是上层场景和安全合同的基线输入，不能替代 wrapper 最新识别的 A 点。移动目标后必须重跑完整动态识别链，不能复用旧 target JSON。

## 树莓派部署

在机械臂树莓派的 ROS2 可用终端执行：

```sh
git clone https://github.com/babanooi/robo-scientist.git
cd robo-scientist
python3 -m pip install --user -e .
cp configs/real_arm_profile_template.json configs/real_arm_profile.local.json
```

编辑 `configs/real_arm_profile.local.json`。模板中的标定版本、工作空间、抓取位姿和放置位姿不能直接用于真实动作；它们必须由 B/D 的当前设备测量值替换。该本地文件已被 Git 忽略。

按硬件组已验证流程启动 Robot SDK 和 Aurora depth camera，并确认下列服务和话题存在：

```sh
ros2 service list | grep -E '^/kinematics/(get_current_pose|set_pose_target)$'
ros2 topic list -t | grep -E '^/depth_cam/(rgb/image_raw|rgb/camera_info|depth/image_raw|depth/camera_info|depth_registered/points)'
```

先在现场单独验证最终基线。`check` 末尾必须同时出现两个放行状态；`pick-place` 的动作状态仍需人工核验物理结果：

```sh
bash ~/armpi_tasks/run_final_dynamic_pick_place.sh check
bash ~/armpi_tasks/run_final_dynamic_pick_place.sh pick-place
```

先启动不含真实控制的桥接服务，确认端口和 Python 环境：

```sh
python3 -m roboscientist.hardware_bridge.server --host 0.0.0.0 --port 8060
curl http://127.0.0.1:8060/health
```

输出必须表明 `mode` 为 `dry_run`、`motion_enabled` 为 `false`。此模式用于网络和部署检查，绝不能被称为真实实验。

为桥接设置当前设备路径和已经实测的软件停止命令。未填写停止命令时，后端会拒绝实机执行：

```sh
export ARMPI_TASK_DIR=/home/ubuntu/armpi_tasks
export ARMPI_WRAPPER=/home/ubuntu/armpi_tasks/run_final_dynamic_pick_place.sh
export ARMPI_RUN_ROOT=/home/ubuntu/armpi_tasks/roboscientist_runs
export ARMPI_EVIDENCE_DIR=/home/ubuntu/armpi_tasks
export ARMPI_STOP_COMMAND='REPLACE WITH THE VERIFIED SOFTWARE STOP COMMAND'
```

完成后端代码审查和现场验证后，才启动实机桥接：

```sh
python3 -m roboscientist.hardware_bridge.server \
  --host 0.0.0.0 --port 8060 --allow-real-motion \
  --backend armpi_final_wrapper_backend:create_backend
```

访问 `/health` 后，只有同时看到 `mode=real_motion`、`motion_enabled=true`、`available=true`、`stop_available=true` 才可进行下一步。

要验证自主反馈而非只验证运动，硬件组还需设置 `ARMPI_RESULT_EVALUATOR=<模块>:<函数>`。该函数接收本次计划、动作记录和证据字典，返回 `outcome`、失败码和真实测量指标。未设置时，后端会完成已批准的动作链，但将结果标记为 `motion_completed_result_unverified`，不会伪造抓取成功或生成错误的优化结论。

当前最终 wrapper 只验证了固定 P0，并没有可核验的候选参数入口。专用后端因此拒绝非 `p0` 版本和非零 `grasp_offset_m`。硬件组完成受限参数接口前，网页上的候选 Skill 只能作为软件建议，不能称为实机 P1 反馈迭代。

## 执行与验收

在另一终端运行一次真实 P0。首次仅限经 B 批准的保守固定场景，人员必须在场：

```sh
ROBO_ALLOW_REAL_ARM=1 python3 -m roboscientist.cli \
  --mode real_arm \
  --real-arm-profile configs/real_arm_profile.local.json \
  --enable-real-arm \
  --data-root data/real-arm-test
```

启动网页和 API：

```sh
ROBO_ALLOW_REAL_ARM=1 python3 -m roboscientist.web.server \
  --host 0.0.0.0 --port 8001 \
  --data-root data/real-arm-test \
  --real-arm-profile configs/real_arm_profile.local.json
```

浏览器打开 `http://<树莓派IP>:8001`，选择“真实机械臂”。“受监督自动迭代”最多运行 P0 和一个候选 P1；每一次仍会重新经过上层安全检查和桥接 `preflight`，不能自动晋升版本。

验证本轮是真实闭环的最小标准：

- `data/real-arm-test/experiments/<experiment_id>/result.json` 的 `data_source` 是 `real_arm`；
- `actions` 非空，含实际动作状态和时长；
- `artifacts` 至少引用本次 check/执行日志和关节数据，视觉可用时还应引用图像；
- 失败时有结构化 `failure` 与相应数值，例如 `position_error_m`、`path_length_m`；
- `POSE_OFFSET`、`GRASP_FAILED` 或 `PATH_BLOCKED` 会在 `data/real-arm-test/skills/` 新建候选版本；只有硬件参数接口完成后，下一轮才允许把该单一参数族用于实机；
- 一次 P1 成功只证明候选有一条证据，不能晋升。P0/P1 需在冻结验证集各至少 10 次后才能作晋升或回滚决定。

## 紧急停止

网页关闭、SSH 断开或 `Ctrl+C` 都不是现场急停。若动作异常，现场监护人优先使用经硬件组验证的物理停止/断电方式；软件侧随后调用 `POST /stop` 或重新回零，并完整保留该次失败记录。任何停止后不得自动续跑。
