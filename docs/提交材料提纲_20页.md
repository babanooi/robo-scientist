# RoboScientist 技术方案材料提纲（20 页以内）

版本：v0.1
适用路线：当前无实机；以纯 Python 软件虚拟工作单元为主，Gazebo/MoveIt2 运行时未验证。
使用方式：这是 PPT/PDF 的页级提纲；最终数字、截图和结论必须来自提交包内可回取的工件。

## 1. 页数与证据原则

建议控制在 14–16 页，预留答辩追问空间。每一页右下角标注：

```text
evidence_source: <campaign_id / experiment_id / test log / code path>
data_source: mock | simulation
claim_level: prototype | verified_simulation | real_arm
```

当前版本可以使用 `prototype` 或 `verified_software_virtual`；legacy Gazebo/MoveIt2 只能写 `simulation_runtime_check`。没有 Gazebo/MoveIt2 或实机证据时，不得把页面标题写成“机械臂实验证明”“路径最优解”或“成功率提升”。

## 2. 推荐页结构

| 页码 | 标题 | 应回答的问题 | 必须引用的工件 |
|---:|---|---|---|
| 1 | 项目名称与一句话价值 | 作品解决什么问题？ | PRD、包级 MANIFEST |
| 2 | 赛题对齐 | 为什么属于方向 1B？ | 赛题矩阵、技术方案 |
| 3 | 问题与研究假设 | 如何证伪，而不是单次演示？ | `research_question`、`hypothesis` |
| 4 | 场景与控制变量 | 哪些条件固定，哪些参数可变？ | `scene_id`、安全配置 |
| 5 | 系统架构 | 任务、计划、执行、评价、反馈如何连接？ | 源码模块图、API 文档 |
| 6 | AI 与确定性程序边界 | Qwen 做什么，安全层做什么？ | Qwen Schema、SafetyCheck |
| 7 | 数据与证据链 | 一轮实验保存什么？ | `ExperimentResult` 字段、目录树 |
| 8 | P0 基线流程 | 初始计划如何执行和记录？ | P0 `plan.json`、`result.json` |
| 9 | 失败归因 | 失败由哪些数值/证据支持？ | `analysis.json`、指标 |
| 10 | P1 候选生成 | 下一轮具体改变什么？ | `candidate_skill.json`、参数 diff |
| 11 | 同条件验证 | 如何保证不是换场景或换口径？ | `same_condition` |
| 12 | 结果与版本决策 | 何时晋升、拒绝或停机？ | `comparison.json`、决策规则 |
| 13 | 前端与 API | 评委如何调用和交互？ | API 示例、前端截图/地址 |
| 14 | 可复现与安全 | 新环境如何启动，如何停止？ | README、测试日志、Stop 规则 |
| 15 | 当前演示结果 | 当前版本真实能证明什么？ | 软件虚拟 campaign、Mock campaign 或 legacy 仿真边界检查 |
| 16 | 局限、风险与下一步 | 哪些尚未完成，如何解除？ | `limitations.md`、验收报告 |

若有经过验证的虚拟实验，可将第 15 页替换为 P0/P1 重复实验统计；若没有，保留“边界诚实披露”比编造实验图表更重要。

## 3. 当前路线建议文案

### 3.1 可以使用的主叙事

> RoboScientist 把抓取任务包装成可审计的科学实验流程：系统从任务文本生成结构化研究问题和实验计划，经过确定性安全门后执行适配器，记录结果并分析失败，再提出只改变一个参数族的候选 Skill。当前提交版本使用纯 Python 软件虚拟工作单元生成可复现轨迹、碰撞预测和评价，在同一数据来源下演示 P0→P1；它不等同于 Gazebo/MoveIt2 或真实实验。

### 3.2 当前路线不能使用的文案

- “机械臂已经自主完成抓取”；
- “Qwen 直接控制机械臂”；
- “路径已达到最优”；
- “P1 成功率提升 X%”（除非有固定条件下的重复统计）；
- “Gazebo/MoveIt2 已验证”（除非有运行日志、轨迹和评价文件）；
- “模型判断抓取成功”（成功必须由独立评价器判定）。

## 4. 图表与截图要求

每张图都要同时显示或在图注中说明：

- 数据来源（`mock` 或 `simulation`）；
- 运行 ID；
- 是否只读/是否发送运动命令；
- 指标定义和单位；
- 生成代码版本或文件哈希。

推荐图表：

1. 闭环架构图：Qwen → Schema → 安全层 → Adapter → Evaluator → Optimizer；
2. P0/P1 参数差异表：只显示一个允许参数族；
3. 指标对照图：在没有重复实验时只展示单次“候选验证”，并标注不可外推；
4. 证据目录树和 SHA256 校验流程；
5. 前端的来源标签、失败状态和仿真未验证提示。

|---|---|---:|---:|---:|---:|---|
| P0 | `mock`/`simulation` | `REPLACE` | `REPLACE` | `REPLACE` | `REPLACE` | 基线/边界 |
| P1 candidate | `mock`/`simulation` | `REPLACE` | `REPLACE` | `REPLACE` | `REPLACE` | 候选，不自动晋升 |

如果样本数为 1，标题应写“单次候选验证”，不要写“成功率”；如果运行时未验证，所有数值应留空或只报告拒绝原因。
