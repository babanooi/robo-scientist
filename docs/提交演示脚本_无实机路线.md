# RoboScientist 无实机提交演示脚本

版本：v0.1
目标时长：5–8 分钟
演示性质：纯 Python 软件虚拟工作单元闭环演示，不是机械臂实机或 Gazebo/MoveIt2 演示。

## 1. 演示前准备

在演示电脑上执行：

```sh
cd /path/to/roboscientist
python3 -m venv .venv
. .venv/bin/activate
python -m pip install -e .
python -m unittest discover -s tests -q
export PYTHON=python
```

启动本地看板（公共 `simulation` 模式默认使用 `VirtualSimulationAdapter`）：

```sh
$PYTHON -m roboscientist.web.server \
  --host 127.0.0.1 \
  --port 8001 \
  --data-root data/submission-demo
```

浏览器打开：<http://127.0.0.1:8001/>

演示前确认：

- 页面顶部数据来源为 `SIMULATION · 软件虚拟工作单元`（若要演示 Mock，可按第 3 节切换）；
- Qwen 状态如未配置则显示“未调用/不可用”；
- 实时实机区域显示“不可用”，没有播放占位视频；
- 没有设置 `ROBO_ALLOW_REAL_ARM=1`；
- 终端能保存完整 API 响应和实验目录。

## 2. 演示主线：软件虚拟 P0 失败 → 反馈 → P1 候选

### 2.1 发起活动

```sh
curl -fsS -X POST http://127.0.0.1:8001/api/campaigns \
  -H 'Content-Type: application/json' \
  -d '{
    "task_text": "把红色方块放到右侧目标区域",
    "scenario": "pose_offset",
    "mode": "simulation",
    "use_qwen": false,
    "auto_run_p1": true
  }' | tee /tmp/roboscientist_campaign_response.json
```

从响应中复制 `campaign_id`，再执行：

```sh
curl -fsS http://127.0.0.1:8001/api/campaigns/<campaign_id> \
  | tee /tmp/roboscientist_campaign_<campaign_id>.json
```

### 2.2 屏幕讲解词

1. **任务输入**：用户只给出“把红色方块放到右侧目标区域”；系统将其解析为 TaskSpec。
2. **科学问题**：本轮不是单次控制，而是检验“调整一个参数族能否降低位置残差”。
3. **P0 运行**：纯 Python 虚拟场景注入稳定的 X 方向偏差；结果包含失败阶段、带符号残差、轨迹和 `safety_events`。
4. **失败分析**：确定性分析器把失败映射到 `POSE_OFFSET`，候选 Skill 只修改 `grasp_offset`。
5. **P1 运行**：系统复用相同任务、场景、目标和安全约束，只替换候选版本；前端展示同条件检查。
6. **结果**：P1 在 `simulation_runtime_verified` 的软件虚拟数据中通过候选验证。强调这证明的是确定性虚拟工作单元中的闭环逻辑，不是实机抓取成功率，也不是 Gazebo/MoveIt2 物理动力学结论。
7. **版本策略**：页面中的 `candidate_only` 表示尚未经过规定的重复实验，不把一次 P1 晋升为稳定 Skill。

## 3. Mock 与 Qwen 展示分支

如需对比最小流程，可将请求中的 `mode` 改为 `mock`；页面会显示 `MOCK · 流程验证`，并明确不生成轨迹/碰撞物理结论。

### 3.1 没有凭证时

保持 `use_qwen=false`，在 Qwen 审计区域说明：

> 当前演示使用明确声明的 deterministic-only 模式。没有真实 Qwen 调用证据，因此不把本轮当作官方 Qwen 证据。

### 3.2 有凭证且已预先验证时

先在启动服务的同一进程环境设置：

```sh
export DASHSCOPE_API_KEY='只在当前进程存在，不写入文件'
export DASHSCOPE_BASE_URL='https://dashscope.aliyuncs.com/compatible-mode/v1'
export QWEN_MODEL='qwen3.7-plus'
export QWEN_TIMEOUT_S='90'
```

请求仅把 `use_qwen` 改为 `true`。展示：

- `planning` 和 `adjustment` 两阶段；
- 模型名、Request ID、Schema 校验状态和 SHA256；
- API Key 未出现在页面、日志或证据包。

若 Qwen 失败，保留结构化错误并停止演示，不临时切到 deterministic-only 冒充成功。

## 4. legacy 仿真边界演示（可选，约 1 分钟）

当前 CLI 的 `--mode simulation` 已用于公共软件虚拟工作台；要展示 legacy
Gazebo/MoveIt2 契约未接通状态，请运行只读检查：

```sh
$PYTHON - <<'PY'
from roboscientist.adapters import SimulationAdapter
print(SimulationAdapter().get_robot_state())
PY
```

预期字典包含：

```text
data_source=simulation
hardware_status=simulation_runtime_unverified
motion_state=unavailable
```

讲解词：

> 这里展示的是 legacy Gazebo/MoveIt2 契约未接通，不是一次实验。系统不会生成虚假的
> ROS 轨迹或成功结论。前面的 `VirtualSimulationAdapter` 是确定性软件虚拟工作单元，
> 二者都不能被说成真实机械臂。

不要把这一段剪辑成“仿真抓取成功”。

## 5. 前端重点画面

按以下顺序截取截图或录屏：

| 画面 | 必须可见 | 讲解重点 |
|---|---|---|
| A | 数据来源标签、任务输入、研究问题 | 任务被转成可证伪实验问题 |
| B | P0/P1 谱系、失败码、候选 Skill | 数据改变了下一轮计划 |
| C | 同条件检查、指标和 candidate 状态 | 不把一次候选当作晋升 |
| D | Qwen 审计卡或 deterministic-only 说明 | 模型调用与确定性程序边界 |
| E | 实机不可用、运行时名称和仿真边界提示 | 不伪造设备或 Gazebo/MoveIt2 结果 |

实时画面框必须保留“没有经过运行时确认的视频地址”之类的限制提示；历史轨迹回放必须标为只读。

## 6. 故障与追问应答

| 追问 | 推荐回答 |
|---|---|
| “机械臂现在动了吗？” | “没有。本次是纯 Python 软件虚拟工作单元；页面明确标注实机不可用。” |
| “P1 成功率提高了吗？” | “只能说当前虚拟模型中的候选指标改善；没有重复实验前不能外推为成功率提升，更不能外推到实机。” |
| “为什么不直接说 Gazebo 仿真成功？” | “当前 Gazebo/MoveIt2 运行时未验证；纯 Python 虚拟工作单元和 ROS 物理仿真是两种不同证据等级。” |
| “Qwen 做了什么？” | “若启用并成功调用，Qwen 只负责研究计划和反馈策略；安全、评价和参数应用由确定性程序约束。” |
| “如何接入实机？” | “替换为已审计的 DeviceAdapter/Bridge，保留同一 ExperimentResult 和证据字段；本包不宣称已完成。” |
| “这是完整完赛作品吗？” | “这是可复现的软件原型提交包。若官方要求实验运行证据，还需补经验证的仿真或实机案例。” |
