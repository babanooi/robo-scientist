# RoboScientist 提交包说明（无实机路线）

版本：v0.1
适用状态：当前没有可接入的 ArmPi 实机；仓库新增了可复现的纯 Python 虚拟工作单元，但 Gazebo/MoveIt2 运行时仍未验证。
适用赛题：赛道一·方向 1B“科学实验任务规划与反馈迭代”。

## 0. 先说结论

本说明用于把当前软件原型整理成可复现、可审计的提交包。它能证明：

- 自然语言任务可以被整理为结构化实验计划；
- 安全检查、执行适配器、结果分析和候选 Skill 版本之间的接口已经连通；
- 在明确标记为 `mock` 的开发数据上，可以演示 P0 失败、反馈决策和 P1 候选验证；
- 在明确标记为 `simulation`、`simulation_runtime_verified` 的纯 Python 虚拟工作单元上，可以生成轨迹、碰撞预测和结构化评价；
- API、前端、测试和证据目录可以被第三方按步骤启动和检查。

它不能证明：

- 机械臂已经连接或完成真实动作；
- Gazebo/MoveIt2 已经完成虚拟运动规划、碰撞检查或轨迹执行；纯 Python 虚拟工作单元不等同于 Gazebo/MoveIt2 或真实机械臂；
- Mock 结果代表真实抓取成功率；
- 已经取得真实实验条件下的性能提升。

如果官方验收把“实验运行与数据获取”作为硬性条件，纯 Python 虚拟工作单元可以作为软件内可复验实验，但能否替代官方认可的物理/动力学仿真需要评审口径确认；它不能替代 Gazebo/MoveIt2 或实机证据。提交材料必须保留这一限制，不能用截图、手册或一次 Mock/虚拟运行掩盖证据缺口。

## 1. 证据等级与允许表述

| 等级 | `data_source` | 当前状态 | 可以表述 | 不可以表述 |
|---|---|---|---|---|
| L0 | `mock` | 已有 | “软件闭环和接口在确定性 Mock 场景通过” | “机械臂完成抓取”“成功率提升” |
| L1a | `simulation` + `simulation_runtime_verified` | 纯 Python 虚拟工作单元已具备 | “在可复现的软件虚拟工作单元中完成轨迹/碰撞/反馈演示” | “Gazebo/MoveIt2 已执行”“物理动力学已验证” |
| L1b | `simulation` + `simulation_runtime_unverified` | 旧 Gazebo/MoveIt2 契约待验证 | “已实现仿真适配器契约，运行环境待验证” | “仿真已执行”“无碰撞轨迹已验证” |
| L2 | `simulation` + 经验证 Gazebo/MoveIt2 | 只有在对应环境真实运行并留证后 | “在指定 Gazebo/MoveIt2 场景完成可复验实验” | 把仿真结果写成实机结果 |
| L3 | `real_arm` | 本路线不具备 | “实机闭环” | 伪造任何 `real_arm` JSON、日志或图片 |

`mock`、未验证的 `simulation` 和历史回放只能用于开发、软件演示或能力边界说明。纯 Python 虚拟工作单元的 `simulation_runtime_verified` 结果可以用于软件虚拟实验演示，但必须写明运行时名称、版本和引擎，不能暗示 Gazebo/MoveIt2 或物理实机。所有材料、前端标签和报告结论必须保持来源一致。

以下是字段模板。它是提交包说明，不是已经发生的实验结果；所有 `REPLACE_*` 必须在冻结时替换，不能留下看似真实的默认值。

```json

  "project": "RoboScientist",
  "direction": "track1-direction1B",
  "git_commit": "REPLACE_WITH_EXACT_COMMIT",
  "generated_at_utc": "REPLACE_WITH_TIME",
  "evidence_policy": {
    "primary_data_source": "simulation",
    "runtime_status": "simulation_runtime_verified",
    "runtime_name": "roboscientist.virtual_workcell",
    "runtime_version": "1.0.0",
    "engine": "python_deterministic",
    "synthetic": true,
    "claims_scope": "reproducible_software_virtual_experiment_only"
  },
  "runs": [
    {
      "run_id": "REPLACE_WITH_RUN_ID",
      "data_source": "simulation",
      "status": "failed",
      "runtime_status": "simulation_runtime_verified",
      "evidence_class": "software_virtual_experiment",
      "artifacts": ["evidence/virtual_simulation_campaign_<id>/experiments/<experiment_id>/manifest.json"]
    }
  ],
  "qwen": {
    "required_for_official_path": true,
    "invocations_included": false,
    "api_key_included": false
```

无实机包可以把 `primary_data_source` 设为 `mock` 或 `simulation`。使用纯 Python 虚拟工作单元时，必须保留 `runtime_name=roboscientist.virtual_workcell`、`engine=python_deterministic` 和 `synthetic=true`；使用 legacy Gazebo/MoveIt2 契约时，必须保留 `simulation_runtime_unverified`。两者都不能改成 `real_arm`。

## 4. 实验/活动证据字段

### 4.1 `campaign.json`

应保留 API 返回的完整活动对象，不要只截取前端文字。至少包括：

- `campaign_id`、`status`、`classification`、`planning_mode`、`use_qwen`；
- `scientific_plan`、`feedback_adjustment`；
- `records[]` 中每一轮的完整实验对象；
- `decision`、`same_condition`、`promotion`；
- `project_policy.minimum_runs_per_version`；
- `qwen.planning`、`qwen.feedback` 的脱敏元数据或结构化失败记录。

当前仓库中 `classification=deterministic_only` 表示显式关闭 Qwen 的本地路径，只能作为软件合同测试；`classification=mock_autonomous` 也只能说明 Mock 数据上的闭环，不是实机自主实验。

### 4.2 `ExperimentResult`

每轮记录至少应保留以下字段：

```text
experiment_id
task_id
adapter
data_source
hardware_status
skill_version
scene_id
status
safety_check
actions[]
outcome
failure（失败时必填）
metrics
artifacts
candidate_skill_version
simulation（仅仿真适配器可填）
```

对于 legacy 未验证仿真，示例应类似下面这样，并明确它是运行时边界检查，不是成功实验：

```json
{
  "experiment_id": "exp-example-simulation-check",
  "adapter": "simulation",
  "data_source": "simulation",
  "hardware_status": "simulation_runtime_unverified",
  "status": "rejected",
  "outcome": {
    "object_grasped": false,
    "object_lifted": false,
    "object_placed": false,
    "position_error_m": null
  },
  "simulation": {
    "runtime_status": "simulation_runtime_unverified",
    "planning_success": false,
    "execution_success": false,
    "collision_detected": null,
    "planner_name": "OMPL",
    "trajectory_points": 0,
    "safety_events": ["simulation_runtime_unverified"]
  }
}
```

该 JSON 仅用于说明 legacy Schema 和限制，不得放入“成功案例”或指标图表作为实验样本。纯 Python 虚拟工作单元的真实输出应由 `VirtualSimulationAdapter` 产生，并附带 `runtime_name`、`engine`、轨迹和评价工件。

### 4.3 Qwen 证据

当使用官方路径时，至少保存规划和反馈两次调用的脱敏记录：

- 模型名、时间、请求 ID/完成 ID；
- 上下文版本、Schema 名称和 `schema_valid`；
- `prompt_sha256`、`request_sha256`、`response_sha256`；
- token 用量（若供应商返回）；
- 结构化输出和安全层最终决策；
- 失败时的错误码、阶段和重试/停止原因。

不得保存 API Key。没有真实 Qwen 调用时，必须在 `MANIFEST.json` 和报告中写 `invocations_included=false`，不要把确定性函数命名成 Qwen 证据。

## 5. 复现步骤

以下步骤只启动本地软件，不连接机械臂；在包内 `README.md` 中固定实际提交号和运行日志路径。

### 5.1 准备环境

```sh
cd /path/to/roboscientist
PYTHON=${PYTHON:-python3}
$PYTHON -m venv .venv
. .venv/bin/activate
python -m pip install -e .
```

项目需要 Python 3.9+ 和 `pydantic>=2,<3`。提交包应记录可重建的 Python 版本和
依赖摘要（例如 `pip freeze`），不要把个人机器的解释器绝对路径写入材料。

### 5.2 回归测试

```sh
python -m unittest discover -s tests -v 2>&1 | tee tests/test_run.log
```

验收只记录测试退出码和测试数量；“测试通过”不等于机械臂或仿真运行通过。

### 5.3 Mock 科研闭环（开发演示）

无 Qwen 凭证时必须显式关闭模型：

```sh
python -m roboscientist.web.server --host 127.0.0.1 --port 8001 --data-root data/submission-demo
```

另开终端：

```sh
curl -fsS -X POST http://127.0.0.1:8001/api/campaigns \
  -H 'Content-Type: application/json' \
  -d '{
    "task_text": "把红色方块放到右侧目标区域",
    "scenario": "pose_offset",
    "mode": "mock",
    "use_qwen": false,
    "auto_run_p1": true
  }' | tee /tmp/roboscientist_mock_campaign.json
```

保存返回的 `campaign_id` 后完整读取（这里先写入临时目录；冻结提交包时再复制到
`api/` 或 `evidence/` 对应目录）：

```sh
curl -fsS http://127.0.0.1:8001/api/campaigns/<campaign_id> \
  | tee /tmp/roboscientist_mock_campaign_detail.json
```

应能看到 P0 的结构化失败、候选 Skill、P1 的同条件验证和 `data_source=mock`。报告中只能把它称为“软件闭环演示”。

### 5.4 Qwen 路径（仅在有权限和凭证时）

在启动进程环境中临时设置密钥，不写入包：

```sh
export DASHSCOPE_API_KEY='REDACTED_AT_RUNTIME'
export DASHSCOPE_BASE_URL='https://dashscope.aliyuncs.com/compatible-mode/v1'
export QWEN_MODEL='qwen3.7-plus'
export QWEN_TIMEOUT_S='90'
```

请求把 `use_qwen` 设为 `true`。若缺少 Key、网络失败或 Schema 无效，API 应返回结构化错误并停止；不能自动降级为 `deterministic_only`。只在真实调用完成并保存脱敏元数据后，才在材料中写“使用 Qwen”。

### 5.5 纯 Python 虚拟实验

公共 Web 服务的 `simulation` 模式默认使用 `VirtualSimulationAdapter`，不依赖 ROS/Gazebo。它会生成确定性轨迹、场景快照、碰撞预测、评价和 SHA256 manifest：

```sh
python -m roboscientist.web.server \
  --host 127.0.0.1 --port 8001 \
  --data-root data/submission-virtual
```

另开终端：

```sh
curl -fsS -X POST http://127.0.0.1:8001/api/campaigns \
  -H 'Content-Type: application/json' \
  -d '{
    "task_text": "把红色方块放到右侧目标区域",
    "scenario": "pose_offset",
    "mode": "simulation",
    "use_qwen": false,
    "auto_run_p1": true
  }' | tee /tmp/roboscientist_virtual_campaign.json
```

应看到两轮 `data_source=simulation`、`hardware_status=simulation_runtime_verified`，并能在
`data/submission-virtual/virtual_artifacts/<experiment_id>/` 找到 `scene.json`、
`trajectory.json`、`evaluation.json`、`execution_trace.json` 和 `manifest.json`。
这证明的是可复现软件虚拟工作单元，不是 Gazebo/MoveIt2 或实机结果。

### 5.6 legacy 仿真边界检查（可选）

当前 CLI 的 `--mode simulation` 使用公共的 `VirtualSimulationAdapter`，会生成
`simulation_runtime_verified` 的软件虚拟实验；它不再是 legacy 契约检查。若需检查
未验证的 Gazebo/MoveIt2 契约，可用以下只读 Python 片段，不会启动 ROS 或发送动作：

```sh
python - <<'PY'
from roboscientist.adapters import SimulationAdapter
print(SimulationAdapter().get_robot_state())
PY
```

该对象的 `hardware_status=simulation_runtime_unverified` 只表示 legacy 运行时未接通，
不能作为成功实验样本。只有在具备 ROS2、Gazebo、MoveIt2、URDF/SDF、控制器和真实轨迹
证据后，才能将 legacy 路径升级为 Gazebo/MoveIt2 验收。

## 6. 前端演示顺序

1. 打开 `http://127.0.0.1:8001/`，先选择并展示顶部的数据来源标签为
   `SIMULATION · 虚拟工作台`（只有需要说明开发兜底时才切换到 Mock）；
2. 展示“研究问题与假设”，说明本轮目标和成功判据；
3. 运行 `pose_offset`，展示 P0 的失败码、带符号残差和候选参数；
4. 展示反馈卡片，指出 P1 只改变一个参数族；
5. 展示同条件检查和 P0/P1 指标；
6. 展示 Qwen 区域：无 Key 时明确“未调用/确定性模式”；有调用时展示脱敏 Request ID 与 SHA256；
7. 展示“实时实机不可用/历史轨迹只读”等限制提示；
8. 展示 Simulation 的运行时名称 `roboscientist.virtual_workcell`、`simulation_runtime_verified` 和 `engine=python_deterministic`；如需说明 legacy 路径，再展示 `simulation_runtime_unverified`，并解释两者不同；
9. 最后展示提交包目录、测试日志和 `SHA256SUMS.txt`。

演示旁白必须使用“软件虚拟工作单元”“候选验证”“确定性模型”“运行时未验证”等词。不要说“机械臂已经自主完成抓取”“Gazebo 已验证”或“路径得到最优解”。

## 7. 冻结前审计清单

- [ ] `git_commit.txt`、源码、测试日志和前端截图属于同一提交；
- [ ] 每个实验对象都有唯一 ID，P0/P1 不覆盖旧文件；
- [ ] 所有数据记录显式写 `data_source` 和 `hardware_status`；
- [ ] 没有把 Mock、历史回放或 unverified simulation 贴成 `real_arm`；
- [ ] Qwen Key 未进入 Git、JSON、截图、录屏和压缩包；
- [ ] Qwen 规划/反馈证据可由请求 ID和 SHA256 对回；
- [ ] 仿真未验证时，报告、前端和 PPT 都写明未验证；
- [ ] API 请求、完整响应、启动命令和 Python 版本已归档；
- [ ] `SHA256SUMS.txt` 覆盖提交包内所有声明性工件；
- [ ] 限制声明与实际运行结果一致；
- [ ] 若官方要求真实实验，已明确列出尚未满足的验收项和补齐计划。

## 8. 建议答辩口径

> 当前版本完成了上层 AI Scientist 软件闭环：任务解析、实验计划、安全门、结果分析、单参数候选 Skill 和同条件回放均可独立复现。纯 Python `VirtualSimulationAdapter` 能生成可审计的确定性虚拟实验数据；本提交环境没有可验证的 ArmPi 实机或 Gazebo/MoveIt2 运行时，因此不将这些结果表述为真实仪器或物理仿真结论。下一步只需替换同一 Adapter 契约下的 Gazebo/实机执行器，并保留相同的证据字段，即可进入更高等级验收。
