# 硬件组 GitHub 拉取与实机闭环验收

日期：2026-08-20

目标设备：ArmPi Ultra / Ubuntu / ROS 2 Humble
首个场景：固定工作台红色长方体 A→B 抓取放置

## 1. 本次验收究竟证明什么

完整验收链是：

```text
P0 计划
→ wrapper check 安全门
→ 实机动作
→ 视觉结果评估
→ 带符号的失败残差
→ 只修改一个参数族的候选 P1
→ 参数 wrapper 确认实际应用
→ P1 实机复验
→ P0/P1 证据包对比
```

以下情况只能算“实机接入”，不能算“自主反馈迭代”：

- 只看到 `pick_place_sequence_completed`；
- 由人看完后口头说成功，但没有结构化结果文件；
- 上层生成了 P1，但实机 wrapper 没有读取候选参数；
- P0 和 P1 使用了同一套固定动作参数；
- 只有单次 P1 成功，就直接宣称 Skill 已进化或晋升。

## 3. 先冻结 P0 成功基线

在现场确认当前脚本仍是最后一次成功版：

```sh
bash ~/armpi_tasks/run_final_dynamic_pick_place.sh check
bash ~/armpi_tasks/run_final_dynamic_pick_place.sh pick-place
```

`check` 必须包含：

```text
STATUS: numeric_safety_passed
STATUS: preflight_passed
```

`pick-place` 可以包含：

```text
STATUS: pick_place_sequence_completed
```

最后一条只证明动作链完成。现场仍需确认木块被夹住、抬起、运输途中未掉落、在 B 点放下。

## 4. 配置上层安全档案

```sh
cp configs/real_arm_profile_template.json configs/real_arm_profile.local.json
```

由硬件负责人核对并填写：标定版本、工作空间、最大速度、最大候选偏移、桥接地址。审核完成后才将：

```json
"allow_real_robot": true,
"motion_enabled": true
```

模板中的 B 点是当前资料记录的 `(0.220, -0.080, 0.030) m`，若现场成功基线不同，先停止接入并统一文档与脚本，不能让上层和 wrapper 使用不同 B 点。

## 5. 配置 P0 wrapper、停止和结果评估

```sh
export ARMPI_TASK_DIR=/home/ubuntu/armpi_tasks
export ARMPI_WRAPPER=/home/ubuntu/armpi_tasks/run_final_dynamic_pick_place.sh
export ARMPI_RUN_ROOT=/home/ubuntu/armpi_tasks/roboscientist_runs
export ARMPI_EVIDENCE_DIR=/home/ubuntu/armpi_tasks
export ARMPI_STOP_COMMAND='替换为硬件负责人已实测的软件停止命令'

export ARMPI_RESULT_EVALUATOR=roboscientist.hardware_bridge.result_file_evaluator:evaluate_result_file
export ARMPI_EVALUATION_TIMEOUT_S=60
```

结果评估器会在每个实验目录写入 `evaluation_request.json`，外部视觉评估进程应监听该文件，并在同目录写入 `evaluation.json`。格式见 `configs/evaluation_result_template.json`。

自主演示必须使用：

```json
"evaluator_type": "vision"
```

`operator` 可用于早期实机核验，但前端会明确显示为人工确认，不计为自主结果判定。

若失败类型是 `POSE_OFFSET`，必须同时返回带符号的三轴残差：

```json
"failure_code": "POSE_OFFSET",
"position_error_xyz_m": [0.010, 0.000, 0.000]
```

只有误差大小而没有方向时，系统不会生成位置补偿候选。

## 6. 实现参数化 P1 wrapper

仓库已提供 `armpi_parameterized_runner.py`。硬件侧只需实现：

```text
/home/ubuntu/armpi_tasks/run_roboscientist_experiment.sh
```

调用合同：

```sh
bash run_roboscientist_experiment.sh check \
  --parameters <本轮skill_parameters.json> \
  --parameters-sha256 <64位sha256>

bash run_roboscientist_experiment.sh pick-place \
  --parameters <本轮skill_parameters.json> \
  --parameters-sha256 <64位sha256>
```

wrapper 必须读取 JSON，把其中参数映射到已审核的高层运动函数，并在映射完成后原样输出：

```text
STATUS: skill_parameters_applied sha256=<同一个64位sha256>
```

`check` 还必须输出两个安全状态，`pick-place` 完成动作链后输出 sequence 状态。只打印 SHA256 但不真正使用参数属于验收失败。

当前允许的参数范围：

| 参数 | 允许范围 |
|---|---|
| `grasp_offset_m[x,y,z]` | 每轴绝对值不超过 0.020 m |
| `approach_height_m` | 0.01–0.10 m |
| `transit_height_m` | 0.05–0.20 m |
| `speed_m_s` | 0.02–0.15 m/s |

上层候选必须只改变一个参数族。当前候选族为 `grasp_offset` 或 `path_profile`；速度和 approach 不参与自动调整。

配置：

```sh
export ARMPI_PARAMETERIZED_WRAPPER=/home/ubuntu/armpi_tasks/run_roboscientist_experiment.sh
export ARMPI_EXPERIMENT_RUNNER=armpi_parameterized_runner:run_experiment
```

## 7. 启动桥接并做无动作准备检查

```sh
cd /home/ubuntu/robo-scientist
python3 -m roboscientist.hardware_bridge.server \
  --host 0.0.0.0 --port 8060 \
  --allow-real-motion \
  --backend armpi_final_wrapper_backend:create_backend
```

另一终端执行：

```sh
python3 scripts/verify_hardware_setup.py \
  --profile configs/real_arm_profile.local.json \
  --require-closed-loop
```

成功标准：桥接、软件停止、结果评估器、候选参数 runner 全部就绪，并且 P0 `preflight` 通过。该脚本不执行 `pick-place`。

## 8. 启动前端并执行两轮实验

```sh
ROBO_ALLOW_REAL_ARM=1 python3 -m roboscientist.web.server \
  --host 0.0.0.0 --port 8001 \
  --data-root data/real-arm-test \
  --real-arm-profile configs/real_arm_profile.local.json
```

打开 `http://<机械臂IP>:8001`。选择“真实机械臂”。顶部四项应显示桥接、停止、结果评估、候选参数均就绪。

先运行 P0。只有 P0 产生可归因失败且有足够证据时，系统才生成 P1。随后点击“运行候选 P1 验证”，或运行一次受监督自动迭代。

## 9. 实机闭环通过标准

必须同时满足：

1. P0 和 P1 的 `data_source` 均为 `real_arm`。
2. P0 结果来自 `vision` 评估器，并有图像/视频证据路径。
3. P0 失败包含结构化失败码；位置补偿必须包含带符号 XYZ 残差。
4. P1 相对 P0 只改变一个参数族。
5. P1 check 和 pick-place 日志都包含与参数文件一致的 SHA256 回显。
6. P1 的 `artifacts.execution_profile` 为 `parameterized_red_cuboid_runner_v1`。
7. P1 再次经过工作空间、速度、偏移、wrapper check 和 IK 安全门。
8. P1 结果再次由视觉评估器产生，不使用 P0 结果或人工口头结论。
9. `data/real-arm-test/experiments/` 同时保留两轮 plan/result/analysis，不覆盖旧实验。
10. P1 仍为 candidate。至少 10 次独立验证前不得晋升或宣传成功率提升。

## 10. 本轮需要交回软件侧的材料

- `/health` 完整 JSON；
- `verify_hardware_setup.py` 完整输出；
- 一次 P0 和一次 P1 的实验目录；
- 两轮 wrapper 日志；
- 两轮 `skill_parameters.json` 与 SHA256；
- 两轮 `evaluation.json` 和视觉证据；
- 参数化 wrapper 源码及其高层函数映射说明；
- 软件停止命令的实测记录；
- 现场异常、拒绝和人工干预记录。

若 P0 能跑而 P1 被拒绝，优先查看前端失败阶段和 bridge 日志。不要通过放宽工作空间、去掉 SHA256 回显或跳过结果评估器来“跑通”。
